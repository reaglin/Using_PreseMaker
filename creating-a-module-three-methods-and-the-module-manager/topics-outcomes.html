Module Topics

Overview of Module Creation in PreseMaker

Introduces the concept of modules in PreseMaker and explains why there are multiple ways to create them. Sets the stage for understanding when and why each method is used.
  • What Is a Module in PreseMaker? — A module is the fundamental unit of content in PreseMaker, representing a self-contained learning or presentation package that can be built, managed, and deployed independently.
  • Why Multiple Creation Methods Exist — PreseMaker offers three distinct methods for creating a module because different workflows and starting points call for different approaches.
  • The Role of the Module Manager — The Module Manager is the central hub in PreseMaker through which all module creation and management actions are initiated and tracked.
  • Setting the Stage: From Empty to Ready — Regardless of which creation method is used, the end goal is the same — bringing a module to a 'ready' state where PreseMaker can generate or display content.
  • Choosing the Right Method: A Preview — Selecting the appropriate creation method depends on where your starting materials are, how the module was originally produced, and how your team collaborates.

Method 1: Generating a New Module with AI

Covers how to use PreseMaker's AI-powered generation feature to create a brand-new module from scratch. Learners explore the inputs required and what the AI produces as output.
  • Overview of AI-Powered Module Generation — PreseMaker's AI generation feature allows learners to create a brand-new module from scratch without any pre-existing files or content.
  • Accessing the AI Generation Option — Learners initiate AI-powered module creation through the Module Manager, which serves as the central hub for all module creation methods.
  • Required Inputs for AI Generation — Before the AI can generate a module, users must supply specific inputs that guide the content and structure of the output.
  • What the AI Produces as Output — Once the required inputs are submitted, PreseMaker's AI generates a structured module ready to be reviewed and built upon.
  • From Empty Module to Content-Ready State — The AI generation method guides users through a progression from an empty module to one that is structured and ready for further content development.

Method 2: Adding an Existing Module Folder from Disk

Explains how to bring a pre-existing module folder stored locally on disk into PreseMaker. Covers the steps and requirements for the folder to be recognized correctly.
  • Overview of Method 2: Adding from Disk — This method allows you to bring a pre-existing module folder that is already stored locally on your computer into PreseMaker without creating anything new from scratch.
  • Locating the Existing Module Folder — Before adding the folder, you must know the exact location of the module folder on your disk.
  • Folder Structure Requirements — For PreseMaker to correctly recognize an existing folder as a valid module, the folder must meet certain structural requirements.
  • Adding the Folder Through the Module Manager — The Module Manager is the central interface used to add an existing folder from disk into PreseMaker.
  • Validation and Recognition by PreseMaker — After pointing PreseMaker to the folder, the application performs a validation check to confirm the folder qualifies as a recognizable module.
  • Next Steps After Adding the Folder — Once the existing folder is successfully added and recognized, it becomes available in PreseMaker for further editing and content generation.

Method 3: Importing from a File or Repository

Describes how to import a module using a file or a remote repository source. Highlights the scenarios where this method is most appropriate and the steps involved.
  • What Is the Import Method? — Importing from a file or repository is the third method for creating a module in PreseMaker, allowing users to bring in a module that already exists outside the current workspace.
  • When to Use This Method — The import method is most appropriate in specific scenarios where the module source is not a local folder already on disk.
  • Supported Source Types — PreseMaker supports two distinct source types for this import method: a local packaged file and a remote repository URL.
  • Steps to Import a Module — The import process follows a guided sequence within PreseMaker to ensure the module is correctly ingested and ready for use.
  • Role of the Module Manager in This Method — The Module Manager serves as the central hub for initiating and completing the import process, providing the interface and feedback needed throughout.

The Module Manager: Central Hub for Module Setup

Introduces the Module Manager interface as the central workspace that organizes and guides users through module creation. Explains how it tracks module status from empty to content-ready.
  • What Is the Module Manager? — The Module Manager is the central workspace in PreseMaker where all module creation and setup activities are organized and managed.
  • Organizing Modules Within the Manager — The Module Manager displays all current modules in a structured layout, giving users a clear overview of what exists and what still needs attention.
  • Tracking Module Status: Empty to Content-Ready — One of the Module Manager's key functions is tracking the lifecycle status of each module, from its initial empty state to being fully ready for content generation.
  • Guiding Users Through the Setup Process — The Module Manager acts as a guide, helping users understand what steps are required to move a module from creation to readiness.
  • Supporting All Three Creation Methods — The Module Manager serves as the unified hub regardless of which of the three creation methods a user chooses to start a module.

From Empty Module to Content-Ready: The Module Lifecycle

Walks learners through the progression a module follows after creation, ending at the point where it is ready for content generation. Reinforces how the Module Manager supports each stage of this lifecycle.
  • The Starting Point: An Empty Module — A newly AI-generated module starts empty and needs its topics generated first; modules added from an existing folder or imported may already contain topics and content.
  • Introducing the Module Manager as Lifecycle Hub — The Module Manager serves as the central interface that tracks and supports a module through every stage of its lifecycle after creation.
  • Progressing Through Lifecycle Stages — After creation, a module passes through a defined sequence of stages before it is ready for content generation.
  • The Role of Configuration in the Lifecycle — Between creation and content readiness, a module typically requires configuration steps that establish the parameters needed for content generation.
  • Reaching the Content-Ready State — The content-ready state is the final stage of the module lifecycle covered in this topic, representing the point at which content generation can begin.
  • How the Module Manager Reinforces Each Stage — The Module Manager does not simply display lifecycle status passively — it actively supports learners by surfacing the right actions and information at each stage.
