Adjusting and Replacing the Module Breakdown

▶

Once an AI-suggested module breakdown has been generated, it is rarely a perfect fit straight out of the box. Course designs evolve, learning objectives shift, and the phrasing or ordering that an AI produces may not match the instructor's vision. PreseMaker therefore provides a layered set of tools that let you work at whatever level of change you need — tweaking a single title, reshuffling the sequence, deepening or narrowing a module's scope, or throwing out the entire structure and starting fresh. Understanding exactly what each operation does, and what it leaves untouched, prevents accidental data loss and keeps your project folder stable throughout the editing process.

Editing Individual Module Titles

The simplest form of adjustment is renaming a module. Every module in the breakdown is displayed with an editable title field. Clicking directly on that field activates inline editing — the text becomes a cursor-ready input without opening any separate dialog or navigating away from the breakdown view. You simply type the replacement name and the change is registered immediately when you click elsewhere or press Enter.

It is important to understand the distinction between a module's display title and its underlying folder name. When PreseMaker first creates a module, it derives a stable folder name from the original AI-generated title — typically by lowercasing it, replacing spaces with hyphens or underscores, and stripping special characters. This folder name is written to disk and is what the application uses internally to locate assets, draft content, and configuration files associated with that module. When you edit the display title afterward, only the human-readable label is updated; the folder name on disk stays exactly as it was. This means that any file paths, links, or references you have already established for that module continue to work correctly even after you rename it several times.

For example, suppose the AI suggested a module titled "Introduction to Data Structures" and the resulting folder was named introduction-to-data-structures. If you change the display title to "Foundations of Data Organisation" to better match your course vocabulary, all existing files remain under introduction-to-data-structures/ and nothing breaks. The learner-facing and author-facing name simply becomes the new label.

Choosing precise, descriptive titles pays dividends later. A title like "Advanced Sorting Algorithms" communicates far more to both co-authors and learners than a generic "Module 4". Custom titles also make the course easier to audit against learning objectives, because you can read down the breakdown list and immediately verify whether every intended outcome has a corresponding module.

Reordering Modules in the Breakdown

The sequence in which modules are presented is as pedagogically significant as their content. A learner who encounters assessment techniques before data collection methods, for instance, will struggle to apply what they have learned. PreseMaker lets you reorder the breakdown either by dragging a module row to a new position in the list or by using explicit up/down arrow controls beside each row — useful when drag-and-drop is impractical on smaller screens or with assistive technology.

When you move a module, PreseMaker updates each affected module's stored order value — a numeric index that determines the sequence in which modules appear across all views, exports, and navigation menus. Crucially, folder names are not changed during reordering. A module whose folder is named module-03-ethics does not get renamed to module-01-ethics just because you moved it to the top of the list; the folder name is a stable identifier, not a position marker. This design means you can reorder freely without invalidating internal links or asset references.

After making several reordering changes, it is good practice to read through the full list top-to-bottom and ask whether the flow makes sense as a learning journey. Specific things to verify:

  • Does each module assume only knowledge that has been covered in earlier modules?
  • Are prerequisite concepts introduced before the modules that depend on them?
  • Do any modules that were designed as a pair or sequence still appear adjacent to each other?
  • Does the overall arc move from foundational concepts toward applied or evaluative work in a way that matches your instructional design model?

If you discover a dependency conflict — for example, a module on "Regression Analysis" sitting before a module on "Descriptive Statistics" — reordering alone resolves it without any need to touch the modules' actual content.

Modifying Individual Module Descriptions or Scope

Beyond the title, each module carries a description and a list of subtopics that define its scope. These can be edited independently without affecting any other module in the breakdown. Clicking on a module row expands its detail panel, revealing text fields for the description and an editable list of subtopics or learning outcomes.

You might narrow a module's scope when the AI has bundled too many distinct concepts into one entry. For instance, an AI-generated module called "Security and Compliance" might list subtopics covering network firewalls, data encryption, GDPR obligations, audit logging, and incident response — enough material for two or three separate modules. Removing some subtopics from this module's detail panel (and later adding a new module to house them) keeps the scope coherent without requiring a full regeneration.

You might broaden a module's scope when the AI has been overly conservative. If a module on "HTTP Basics" omits HTTPS and TLS, you can add those as subtopics directly in the detail panel to signal that the module should address the secure transport layer as well.

A key operational advantage of this approach is that editing one module's description or subtopic list does not trigger a full regeneration of the entire breakdown. The rest of the structure stays exactly as it is. This makes targeted modifications safe and low-risk — you are doing surgical editing, not reconstructing the building from the ground up.

Replacing the Entire AI-Suggested Structure

Sometimes incremental edits are not enough. If the AI-generated breakdown is structured around the wrong framework, covers the wrong depth, or simply does not resemble the course you are trying to build, replacing the entire structure is the right move. PreseMaker provides a Regenerate or Replace Breakdown option that discards the current proposal and asks the AI to produce a completely new module structure from scratch.

Before triggering this action, there is one critical caution: any manual edits made to the existing breakdown will be permanently lost. If you have spent time renaming modules, writing custom descriptions, or carefully arranging the order, none of that work carries over to the new proposal. PreseMaker will replace the entire structure with a freshly generated one. The recommended habit is to take a note — or a screenshot — of any elements from the current breakdown that you want to preserve, so you can re-apply them to the new structure after it is generated.

Multiple regeneration attempts are permitted. If the first replacement proposal is still not quite right, you can regenerate again. Each attempt is independent, giving you a different AI-produced interpretation of your inputs. There is no penalty for regenerating several times; the goal is to find a starting structure that is close enough to your ideal that the remaining gap can be closed through targeted edits rather than another full regeneration.

Regenerating a Proposal with Revised Inputs

Rather than regenerating with identical inputs and hoping for a different result, a more effective strategy is to revise the inputs before triggering regeneration. The inputs PreseMaker passes to the AI typically include:

  • A written course description or learning objective statement
  • Uploaded or pasted source materials (syllabi, reference documents, subject outlines)
  • Any configuration parameters you have set, such as the desired number of modules, audience level, or instructional approach

If the previous breakdown produced modules that were too high-level, adding more granular source material or expanding your description to mention specific topics you want covered will steer the AI toward a more detailed structure. If the modules were too numerous and granular, simplifying your description or reducing the requested module count gives the AI permission to consolidate.

When you trigger the regeneration, PreseMaker bundles your revised description and updated source materials together and passes them to the AI model. The resulting proposal reflects these adjusted parameters rather than simply re-running the original request. Once the new proposal appears, comparing it side-by-side with your notes from the previous version helps you make an informed judgment: does the new structure better serve your learning objectives? Are the module boundaries cleaner? Is the sequence more logical? This comparison step prevents you from accepting a new proposal out of impatience only to discover later that the previous one had strengths worth preserving.

Confirming and Locking the Final Breakdown

When you are satisfied that the module titles are accurate, the sequence is logical, the descriptions are appropriately scoped, and the structure as a whole reflects your course design, you confirm the breakdown. This final confirmation step is deliberate — PreseMaker uses it as the trigger to write the structure to the course's on-disk folder system, creating the actual directories that will house each module's content, assets, and configuration.

Before confirming, a final review pass is strongly recommended. The following checklist captures the most important things to verify:

  • Every module title accurately reflects what that module will teach
  • The module sequence flows logically from foundational to advanced, or follows whatever pedagogical pattern the course demands
  • No two modules overlap significantly in scope
  • All major course learning objectives map to at least one module
  • The total number of modules is realistic for the course's intended duration

Once you confirm, the structure is locked in the sense that the folder system has been committed to disk. Individual modules can still be opened and edited — you can continue to refine titles, update descriptions, and adjust subtopics — but performing a wholesale replacement of the entire breakdown at this point would require restarting the breakdown generation process from the beginning, because the on-disk structure would need to be rebuilt. This is why the confirmation step is framed as a significant threshold: it is the point at which the course structure moves from a proposal into an active project.

The table below summarises what each type of adjustment changes and what it leaves unchanged, providing a quick reference for deciding which operation is appropriate for a given situation.

Operation What Changes What Stays the Same Risk of Data Loss
Edit module title Display name of that module Folder name, all other modules, file paths None
Reorder modules Stored order value for affected modules Folder names, module content, descriptions None
Edit module description / subtopics Description and subtopic list for that module All other modules, folder names, order None
Regenerate / Replace breakdown Entire module structure (titles, order, descriptions) Nothing from the previous proposal is retained High — all manual edits are lost
Regenerate with revised inputs Entire module structure, based on updated parameters Nothing from the previous proposal is retained High — all manual edits are lost
Confirm / Lock breakdown Writes folder structure to disk; locks wholesale replacement Individual module editing remains available None (but reverting requires restarting the process)
