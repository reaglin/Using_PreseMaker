Generating a Module Breakdown from Source Material — Module Topics

How PreseMaker Analyzes Source Material

Explores the process by which PreseMaker reads and interprets uploaded source material to identify key themes and content areas. Learners understand what drives the AI's initial structural proposals.
  • Uploading Source Material to PreseMaker — The process begins when a user uploads source material into PreseMaker, providing the raw input the AI will use to build a course structure.
  • Reading and Parsing the Content — Once material is uploaded, PreseMaker reads through the full text to parse its language, structure, and subject matter.
  • Identifying Key Themes and Content Areas — PreseMaker uses its analysis to surface the dominant themes and distinct content areas present in the source material.
  • Generating an Initial Structural Proposal — Based on its thematic analysis, PreseMaker produces an initial module breakdown that reflects the key content areas it has identified.
  • What Drives the AI's Decisions — Understanding the factors that influence PreseMaker's structural suggestions helps learners evaluate and refine the AI's proposals more effectively.

Understanding the AI-Suggested Module Breakdown

Introduces the initial module structure that PreseMaker proposes after analyzing source material. Learners examine what a generated breakdown looks like and what information it contains.
  • What the AI-Generated Breakdown Looks Like — After PreseMaker analyzes your source material, it proposes an initial module structure presented as a breakdown of the course content.
  • How PreseMaker Analyzes Source Material — PreseMaker processes the source material you provide and uses AI to identify logical divisions and themes within the content.
  • Information Contained in Each Suggested Module — Each module in the AI-suggested breakdown contains specific information to help you evaluate whether it is appropriate for your course.
  • Purpose of the Initial Breakdown — The AI-suggested breakdown is intended as a draft structure, not a final decision, giving learners a foundation to work from.
  • Evaluating the Suggested Structure — Once the breakdown is displayed, learners are expected to review it critically to determine whether the proposed modules are accurate and useful.

Accepting the Proposed Module Structure

Covers the workflow for reviewing and accepting the AI-generated module breakdown when it meets the course design requirements. Learners practice confirming a structure to move forward in the authoring process.
  • Reviewing the AI-Generated Module Breakdown — Before accepting a proposed structure, learners must carefully evaluate the AI-generated module breakdown against their course design goals.
  • Criteria for Accepting the Structure — A proposed module breakdown is ready to accept when it sufficiently meets the course design requirements without needing significant changes.
  • Performing the Accept Action in PreseMaker — Accepting the proposed structure is a deliberate action within the PreseMaker interface that confirms the breakdown and moves the authoring process forward.
  • What Happens After Acceptance — When a learner accepts the module breakdown, PreseMaker uses that structure as the foundation for all subsequent authoring steps.
  • Committing to the Structure vs. Exploring Alternatives — Accepting the structure is a commitment to move forward, making it important to distinguish this action from options to adjust or replace the breakdown.

Adjusting and Replacing the Module Breakdown

Focuses on how to modify individual modules or replace the entire AI-suggested structure with an alternative. Learners practice editing titles, reordering modules, and regenerating proposals.
  • Editing Individual Module Titles — After the AI proposes a module breakdown, learners can directly edit the title of any individual module to better reflect their course goals.
  • Reordering Modules in the Breakdown — The sequence of modules in the AI-generated structure can be rearranged to create a more logical instructional flow.
  • Modifying Individual Module Descriptions or Scope — Beyond renaming, learners can adjust the scope or description of a single module without altering the rest of the breakdown.
  • Replacing the Entire AI-Suggested Structure — If the AI-proposed module breakdown does not meet course requirements, learners can discard it entirely and request a new proposal.
  • Regenerating a Proposal with Revised Inputs — Learners can guide the regeneration by revising the module description or the source materials before requesting a new breakdown.
  • Confirming and Locking the Final Breakdown — Once the module structure has been adjusted or replaced to satisfaction, learners confirm the breakdown to lock it in as the basis for further course development.

Course and Module Storage as Folders on Disk

Explains how PreseMaker organizes courses and modules as a folder hierarchy on the local file system. Learners understand the relationship between the on-screen structure and the underlying file storage.
  • Courses as Top-Level Folders — In PreseMaker, each course you create is stored as a dedicated top-level folder on your local file system.
  • Modules as Subfolders Within the Course Folder — Each module within a course is represented as a subfolder nested inside the parent course folder.
  • Relationship Between On-Screen Structure and File Hierarchy — The visual course and module tree displayed in PreseMaker directly mirrors the folder hierarchy stored on the local file system.
  • Contents Stored Inside a Module Subfolder — Each module subfolder contains all the files needed to define and deliver that specific module's content.
  • Practical Benefits of the Folder-Based Storage Model — Organizing courses and modules as folders on disk provides learners and authors with transparent, portable, and easily manageable content storage.
