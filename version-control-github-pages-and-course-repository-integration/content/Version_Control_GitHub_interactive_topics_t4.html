Other Sharing Options: Archive Export and iFrame Embedding

▶

Beyond the primary methods of sharing course content through linked repositories or direct distribution of URLs, PreseMaker offers two additional sharing options that address distinct needs: archive export and iFrame embedding. These tools expand the flexibility of how a course can be packaged, transferred, preserved, and presented to learners. Understanding both options — what they produce, when each is appropriate, and how they compare to one another — equips instructors and course designers to make informed decisions about distributing their work in a variety of real-world contexts.

Archive export treats a course as a self-contained bundle, packaging all of its materials into a single portable file that can travel independently of any network connection or online repository. iFrame embedding, by contrast, treats a published course as live content that can be surfaced inside another web page, allowing learners to engage with the material without ever leaving a familiar institutional portal or website. These two approaches are not mutually exclusive; an instructor might archive a course for backup and safekeeping while simultaneously embedding the published version inside a learning portal for daily learner access.

Exporting a Course as an Archive File

The archive export process is initiated from within the PreseMaker interface. When an instructor triggers an export, PreseMaker collects all of the course's materials — content pages, media references, structure, and settings — and packages them into a single archive file. This file is self-contained: it does not depend on a live connection to a repository or an active internet session to be created, stored, or later used. The export is a fully offline operation from start to finish.

The resulting archive file is designed specifically for re-import into PreseMaker. When another instructor or the same instructor working in a different PreseMaker environment imports the archive, the course is restored in an editable state. This means the recipient does not receive a static or view-only copy; they receive a fully functional course that can be continued, adapted, localized, or otherwise modified to suit the new context. This distinguishes archive export from simply sharing a published web link, where the recipient can view the course but cannot edit or build on it.

Because no network connection is required, archive export is particularly reliable in environments where internet access is limited, inconsistent, or restricted by institutional policy. An instructor can produce the archive file on any machine running PreseMaker, copy it to a USB drive or attach it to an email, and hand it off to a colleague in an entirely different organization — no shared repository, no cloud account, and no internet connection needed on either end at the time of transfer.

When to Use Archive Export

Archive export is the right choice in several practical scenarios. The most straightforward is a direct handoff: when one instructor or institution has developed a course and wants to transfer full ownership or a working copy to another instructor or institution for local use. The recipient imports the archive into their own PreseMaker environment and immediately has access to all the content in an editable form, ready to customize for their own learners.

Archive files also function as point-in-time snapshots of a course. Unlike version control history, which captures incremental changes over time and requires a connected repository to access, an archive export captures the exact state of the course at the moment of export and stores it as a standalone file. This makes archive export a useful form of manual backup. An instructor who has just completed a major revision, for example, might export an archive before beginning the next round of changes, creating a reliable restore point that exists entirely outside of the version control system.

When an archived course is imported, PreseMaker restores the content so that it is ready to be worked on again. The import does not merely display the course — it reconstitutes it as a live PreseMaker project. This means that even if the original source files were lost or the original repository became inaccessible, an archive file would be sufficient to recover the course and resume development.

Generating an iFrame Embed Code

iFrame embedding serves a fundamentally different purpose: rather than transferring a course from one editing environment to another, it displays a published course inside another web page. PreseMaker generates the embed code automatically, so instructors do not need to write any HTML themselves. The generated code is a short snippet containing an <iframe> element with a src attribute pointing to the published course's web address, along with any relevant dimension and display attributes.

Once the code is copied from PreseMaker, it can be pasted into the HTML of any web page that supports iFrame embedding. Common targets include course portals, institutional learning management systems that allow custom HTML blocks, departmental websites, and any other web environment where an administrator has the ability to insert raw HTML. The iFrame acts as a window: from the learner's perspective, the course content appears to be part of the surrounding page, displayed within the same browser tab, inside the host site's layout and branding.

A key characteristic of iFrame embedding is that the embedded content is live. The iFrame does not contain a copy of the course; it points to the published version at its web address and loads it dynamically each time a learner visits the host page. This means that whenever the published course is updated — for example, when an instructor pushes a new version to GitHub Pages and the published site refreshes — the embedded view automatically reflects those changes. No update to the embed code itself is required, and no action is needed on the part of whoever manages the host page.

When to Use iFrame Embedding

iFrame embedding is the appropriate choice when an institution or instructor wants learners to experience course content within a branded, controlled environment without being redirected to an external URL. Rather than sending learners away from the institutional portal to a separate site, the portal can contain the course directly, maintaining a consistent visual identity and user experience throughout the learner's session.

Because iFrame embedding requires a live web address to load content from, the course must already be published to a publicly accessible location — for example, a GitHub Pages URL — before an embed code can be generated or used effectively. If the course is not yet published, or if its published address is not publicly reachable, the iFrame will have nothing to display. This is an important prerequisite: archive export can be performed at any stage of a course's development, but iFrame embedding is only meaningful once a published version exists online.

The host page — the page into which the iFrame is embedded — controls the dimensions and placement of the embedded frame. Whoever manages the host page can set the width and height of the iFrame to match the surrounding design, position it within the page layout, and adjust it over time as the site's design evolves. The course content itself scales or scrolls within those dimensions, allowing the same published course to be embedded at different sizes across different pages or sites without any change to the course itself.

Comparing Archive Export and iFrame Embedding

Although both options extend the ways a course can be shared, they differ fundamentally in what they produce and what they require. The table below summarizes the key distinctions:

Characteristic Archive Export iFrame Embedding
Output A portable file that can be imported and edited in PreseMaker An embed code that displays a live published course inside another web page
Requires published web address No — works entirely offline Yes — the course must be published to a publicly accessible URL
Recipient can edit the course Yes — importing the archive restores a fully editable project No — learners and host page visitors view only; they cannot edit
Reflects future updates automatically No — the archive captures a fixed snapshot at the time of export Yes — the embedded view loads the current published version each time
Primary use cases Content handoff between instructors or institutions; manual backup and restore points Integrated in-page presentation to learners within a branded portal or website
Network connection required Not at time of export or import Required for the embedded content to load in the host page

In practice, the choice between archive export and iFrame embedding is rarely a matter of one being better than the other in an absolute sense. They solve different problems. Archive export is the right tool when the goal is to move a course as an editable artifact — to transfer it, back it up, or allow someone else to build on it. iFrame embedding is the right tool when the goal is to present a course to learners in an integrated, branded environment where the published content should appear seamlessly within an existing web page. Both options can be used alongside one another, and both complement the broader suite of sharing workflows that PreseMaker supports.
