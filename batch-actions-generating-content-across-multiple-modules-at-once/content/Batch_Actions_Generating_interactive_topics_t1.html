Introduction to Batch Actions in Course Manager

▶

When building a course with multiple modules, one of the most time-consuming challenges is populating each module with the right type of generated content. Doing this module by module — opening each one individually, triggering content generation, waiting for results, and then moving to the next — can turn what should be a streamlined workflow into a slow, repetitive process. The Batch Actions feature in Course Manager is designed specifically to eliminate that inefficiency. It allows instructors to initiate a single content generation operation that reaches across an entire course structure, touching many modules at once rather than requiring individual attention for each one.

What Are Batch Actions?

Batch Actions are a course-level feature in Course Manager that enable instructors to trigger content generation across multiple modules simultaneously through a single operation. Rather than navigating into each module and manually initiating generation, an instructor sets up one batch run from the course view, selects the target modules, chooses the type of content to generate, and lets the system do the work across all of them at once.

The key distinction here is that Batch Actions operate at the course level. This means they are not found inside any individual module's settings or editing interface. They exist one level up — in the course view — because their purpose is inherently course-wide. A single batch run can affect just a handful of modules or every module in the course, depending on what the instructor selects. This architectural placement reflects the scope of the feature: it is a tool for managing a course as a whole, not for fine-tuning a single module.

Before Batch Actions existed, an instructor building a twenty-module course would have needed to generate content twenty separate times, repeating the same steps over and over. Batch Actions replace that repetitive manual workflow with a single, unified operation.

Purpose of Batch Actions

The primary purpose of Batch Actions is to save time and ensure consistency when generating content across a multi-module course. These two goals are closely connected: when you automate the same operation across many modules at once, you not only finish faster, you also guarantee that each affected module receives the same type of generated content under the same conditions, rather than risking variation that can occur when repeating a manual process many times.

Consider a scenario where an instructor is building a certification course with fifteen modules. They want every module to have a quiz. Without Batch Actions, they would open each module, navigate to the quiz generation option, initiate generation, and repeat that process fifteen times. With Batch Actions, they select all fifteen modules from the course view, choose the Quiz content type, and initiate one batch run. The system handles the rest uniformly.

This makes Batch Actions especially valuable during the initial build phase of a large course, when the course structure exists but the content within each module still needs to be generated. It supports instructors in managing large course builds more effectively within the Course Manager environment by compressing what could be hours of repetitive work into a single, efficiently managed operation.

Types of Content That Can Be Generated

Batch Actions support several specific content types. Each batch run is focused on one content type at a time — the instructor selects the desired type before initiating the run, and that selection determines what gets generated across the chosen modules. The available content types are:

  • Module Topics and Outcomes — These are generated together as a paired set. Topics define the subject matter covered in a module, while Outcomes describe what a learner should be able to know or do after completing it. Generating both together in a batch ensures that every selected module receives a coherent structure of topics and their associated learning outcomes.
  • Quizzes — Assessment content is generated for each selected module. Running this as a batch operation means every selected module receives a quiz in one operation, rather than requiring the instructor to generate assessments one module at a time.
  • Presentations — Slide-based or structured presentation content is generated for each selected module, useful for creating lecture-style or visual learning materials across the course.
  • Text Documents (such as Topic Details) — Written content documents, including detailed topic explanations, are generated for each selected module. Topic Detail documents, for example, provide thorough written coverage of a module's subject matter and are a common use case for batch generation.

Because only one content type is selected per batch run, instructors who need multiple content types across their modules will run separate batch operations for each type. For example, an instructor might first run a batch to generate Module Topics and Outcomes across all modules, then run a second batch to generate Quizzes, and a third to generate Topic Detail documents. Each run is independent and focused.

Course-Level Access to Batch Actions

Finding and using Batch Actions requires navigating to the course view in Course Manager — not into any specific module. This is an important detail for instructors who are accustomed to working inside individual modules, because the Batch Actions controls will not appear within a module's own interface. They are only accessible from the higher-level course view, where the full list of modules is visible and manageable as a group.

This placement is intentional and logical. Because Batch Actions span multiple modules, it makes sense for them to live at the level where all those modules are visible and selectable together. Placing the feature at the course level also reinforces an important workflow habit: when you want to act on many modules at once, you work from the course view. When you want to act on one module's content in detail, you work from within that module.

Scope of a Batch Run

One of the most important aspects of Batch Actions is that instructors have precise control over which modules are included in any given batch run. The feature does not force an all-or-nothing approach. Instructors can choose to include every module in the course, or they can select a specific subset — for example, only the modules that have not yet had quizzes generated, or only the first five modules of a course that is still being built incrementally.

This selective scope is critical for practical course management. A course is rarely built all at once or updated all at once. An instructor might add three new modules to an existing course and need to generate Topic Details only for those new modules, without regenerating content for the modules that are already complete. Batch Actions accommodate this by letting the instructor select only the new modules for the batch run.

The following table summarizes the key characteristics of a batch run:

Characteristic Details
Where it is initiated Course view in Course Manager (not inside individual modules)
Content types available Module Topics & Outcomes, Quizzes, Presentations, Text Documents (e.g., Topic Details)
Content types per run One content type per batch run
Module selection All modules or a specific subset, chosen by the instructor
Primary benefit Saves time and ensures consistency across a multi-module course

In summary, Batch Actions represent a significant productivity feature for instructors working with multi-module courses in Course Manager. By understanding that the feature lives at the course level, generates one content type per run, and applies that generation to whichever modules the instructor selects, instructors can plan their course-building workflow efficiently — running targeted batch operations in sequence to fully populate a course with generated content in a fraction of the time it would take module by module.
