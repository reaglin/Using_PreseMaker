Method 2: Adding an Existing Module Folder from Disk

▶

When working with PreseMaker, there are situations where a module folder already exists on your local disk — perhaps from a previous working session, a backup, or work done on another machine that has since been transferred over. Rather than recreating the module from scratch, PreseMaker provides a dedicated method for bringing that existing folder directly into the application. This is referred to as Method 2: Adding an Existing Module Folder from Disk. Understanding this method thoroughly will save you time and help you avoid common pitfalls that arise when the folder is not properly prepared or located.

The fundamental principle behind this method is straightforward: PreseMaker references the folder's location on your disk rather than duplicating or importing its contents into a separate internal store. This means the module data stays exactly where it is, and PreseMaker simply points to it. As a practical consequence, if you move or rename the folder after adding it, PreseMaker may lose track of it. It is therefore important to settle on a permanent, accessible location for the folder before you begin the process.

This method is particularly well suited to a few common scenarios. If you started building a module in an earlier PreseMaker session and the project folder is still intact on your drive, you can re-attach it without losing any of the work already done. Similarly, if a colleague prepared a module folder and copied it to your machine, you can bring it into your own PreseMaker environment using this same approach. The key prerequisite in every case is that the module folder must already exist on your local disk before you begin.

Locating the Existing Module Folder

Before opening PreseMaker, it is good practice to confirm the precise location of the module folder using your operating system's file explorer or terminal. Navigate to the directory where the folder is stored and verify a few important conditions:

  • Accessibility: The folder must be fully accessible to your user account. Folders that are locked by another process, set to read-only at the system level, or protected by permissions that exclude your account can cause PreseMaker to fail during the validation step.
  • Visibility: Ensure the folder is not hidden. Some transfer or archiving tools mark folders as hidden on Windows or prepend a dot to the folder name on macOS and Linux. PreseMaker's browser dialog may not display hidden folders by default, and even if you type the path manually, certain hidden-folder restrictions can interfere with access.
  • Drive connectivity: If the folder resides on an external drive, a network share, or a cloud-synced location, confirm that the drive is mounted and fully synced before proceeding. A folder path that points to a disconnected drive will appear broken to PreseMaker, even if the path string looks correct.
  • Full path notation: Make a note of the complete, absolute path to the folder — for example, C:\Users\YourName\Projects\ModuleName on Windows or /Users/yourname/projects/ModuleName on macOS. You will likely need to supply this path during the import step, and having it written down or copied to your clipboard avoids transcription errors.

Folder Structure Requirements

Not every folder on your disk can be recognized as a PreseMaker module simply by pointing the application at it. PreseMaker performs a structural inspection of the folder, and the folder must meet specific criteria to pass that inspection. Understanding these requirements helps you diagnose problems if recognition fails.

  • Configuration markers: PreseMaker expects to find one or more configuration or manifest files inside the folder that identify it as a legitimate module. These files are typically created automatically when you first build or export a module through PreseMaker. If the folder was assembled manually or came from a non-standard source, these marker files may be absent, causing the recognition step to fail.
  • Naming conventions: Subfolders and key files within the module folder must follow the internal naming conventions that PreseMaker uses. For example, asset subfolders, content definition files, and metadata files are expected to have specific names. Renaming these components — even with minor capitalization differences on case-sensitive file systems — can break recognition.
  • Completeness and integrity: A partially transferred folder, one that was interrupted mid-copy, or one whose files have become corrupted may pass some checks but fail others. PreseMaker may flag specific missing or unreadable files. In these cases, the safest approach is to obtain a fresh, complete copy of the module folder from the original source before attempting to add it again.

A helpful way to think about the structure requirements is to compare a known-good module folder against the one you are trying to add. If you have a module that PreseMaker already recognizes, you can inspect its folder layout and use it as a reference template:

Component Expected Location Purpose
Module manifest file Root of the module folder Identifies the folder as a PreseMaker module and stores metadata
Content definition file(s) Root or designated subfolder Defines topics, subtopics, and content structure
Assets subfolder Named subfolder within the module folder Holds images, media, and other supporting files
Configuration subfolder Named subfolder within the module folder Stores settings, style preferences, and generation parameters

Adding the Folder Through the Module Manager

With the folder confirmed to be accessible and structurally sound, you are ready to bring it into PreseMaker. The Module Manager is the central hub for all module-related operations within the application, and it is where this method is initiated.

  • Open PreseMaker and navigate to the Module Manager. Depending on your version of PreseMaker, this may be accessible from the main dashboard, a dedicated menu option, or a sidebar panel.
  • Within the Module Manager, look for the option to add an existing module from disk. This is typically labeled distinctly from the option to create a brand-new module, so take care to select the correct action. Choosing the wrong option could initiate a new-module creation workflow instead of the import workflow.
  • You will be presented with either a browse dialog — a standard operating-system file picker — or a path-entry text field where you can type the folder path directly. Both methods lead to the same outcome. Using the browse dialog is generally more reliable because it eliminates the risk of path typos, while typing the path directly can be faster if you already have it copied to your clipboard.
  • Select or enter the path to your module folder and confirm your selection. PreseMaker will immediately begin its scan of the folder upon submission.

Validation and Recognition by PreseMaker

Once the folder path is submitted, PreseMaker does not simply trust that the folder is valid — it runs a validation process to confirm that the folder contains everything it needs to function as a module within the application.

During validation, PreseMaker checks for the presence of required files, inspects configuration markers for correctness, and verifies that key structural elements are intact. This process happens quickly in most cases, but for large module folders with many assets, it may take a few moments.

  • Successful validation: If the folder passes all checks, it will appear as a new entry in the Module Manager's module list. The module's name, as stored in its manifest, will be displayed alongside any other modules you have previously created or imported. From this moment, PreseMaker treats this module exactly as if it had been created natively within the current session.
  • Failed validation: If the folder does not pass validation, PreseMaker will typically display an error message indicating what went wrong. Common error causes include missing manifest files, unexpected folder structures, or unreadable files. Use the error details to diagnose the issue — for instance, a missing manifest file suggests the folder may not be a genuine PreseMaker module folder, while a permissions error points to an access problem that needs to be resolved at the operating system level.
  • Partial recognition: In some edge cases, PreseMaker may recognize the folder as a module but flag certain elements as incomplete or outdated. This can happen when the module was created with an older version of PreseMaker. The application may offer to upgrade or repair the module structure automatically, which is generally safe to accept.

Next Steps After Adding the Folder

Once the module has been successfully validated and added, it becomes a fully functional part of your PreseMaker workspace. The transition from "folder on disk" to "active PreseMaker module" is seamless from this point forward.

  • The module will appear in the Module Manager list alongside all other modules you have created or imported. You can click on it to select it and begin interacting with it just as you would any other module.
  • Before making any changes, it is advisable to open the module and review its existing content. This lets you confirm that the import was successful, that all topics and subtopics are present, and that any assets or media referenced within the module have loaded correctly. Missing assets are a common symptom of a folder that was transferred without its subfolder contents intact.
  • Once you have confirmed the module's content is complete and correct, it is fully ready to be used with PreseMaker's content generation tools. You can edit topics, add new subtopics, run content generation processes, and export output just as you would with any module that was created from scratch within PreseMaker.
  • As a final best practice, consider keeping a note of the folder's location on disk — especially if it resides outside your default PreseMaker working directory. Because PreseMaker references the folder rather than copying it, keeping the folder in a stable, backed-up location protects your work from accidental loss.
