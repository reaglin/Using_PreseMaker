The Module Manager: Central Hub for Module Setup

▶

When you begin working with modules in PreseMaker, nearly every action you take flows through a single, unified interface: the Module Manager. Rather than scattering configuration options across multiple screens or requiring you to jump between different areas of the application, the Module Manager brings everything together into one place. It is the command center from which you start new modules, monitor their progress, configure their settings, and ultimately prepare them for content generation or authoring. Understanding how the Module Manager works — and why it is designed the way it is — is the foundation for working efficiently in PreseMaker.

The Module Manager is not simply a list of files or a passive directory. It is an active workspace that responds to what you have done and tells you what still needs to be done. From the moment you launch PreseMaker and decide to work with a module, the Module Manager is where that work begins and where it is coordinated from start to finish.

What Is the Module Manager?

At its core, the Module Manager is the primary interface users interact with when starting, tracking, or configuring any module. Before it existed as a consolidated hub, users of similar authoring tools often had to navigate away to separate screens to complete different setup tasks — perhaps visiting one screen to name a module, another to set its source, and yet another to configure generation options. The Module Manager eliminates that fragmentation entirely. Every module-related action is surfaced in one location, so your workflow is never interrupted by unnecessary navigation.

Accessing the Module Manager is typically the first step after launching PreseMaker and deciding to work with a module. This immediacy is intentional: the design philosophy is that a user who has decided to work on a module should be able to reach the relevant controls without delay or detour. The moment you open or create a module, the Module Manager is your context, and it remains your context throughout the setup process.

This consolidation has a practical benefit that becomes especially clear when you are managing multiple modules simultaneously. Because all module-related actions live in one interface, you never lose your place. You do not need to remember which screen controls which aspect of setup — the Module Manager surfaces everything you need based on where you are in the process.

Organizing Modules Within the Manager

One of the Module Manager's most important organizational features is that each module appears as a distinct entry within the interface. Rather than presenting modules as identical rows in a flat list, the Module Manager gives each module enough visual identity that you can quickly locate and select the one you want to work on, even when many modules are present.

This distinction extends to helping users recognize where each module stands in the overall process. At a glance, you can distinguish between a module that was just created and has no content yet, a module that is partially configured, and a module that is fully prepared and ready for the next stage. This at-a-glance differentiation reduces the cognitive overhead of managing a complex project with many moving parts.

Importantly, the Module Manager supports working on several modules from the same interface without losing context. If you are setting up one module and need to quickly check the status of another, you can do so within the same workspace. There is no need to close one module's context and open another in a completely different part of the application. This side-by-side management capability is especially valuable for instructional designers and content teams who are simultaneously developing multiple learning modules at different stages of completion.

Tracking Module Status: Empty to Content-Ready

One of the Module Manager's most practically useful features is its status tracking system. Every module moves through a lifecycle, and the Module Manager makes that lifecycle visible at every step.

When a module is first created — regardless of how it was created — it begins in an empty status. This status is an explicit signal: no content has been added yet, no configuration has been applied, and the module is essentially a clean slate. The empty status is not a problem or an error; it is simply the correct starting point, and the Module Manager treats it as such by immediately surfacing the actions needed to move forward.

As you complete setup steps — adding source content, configuring generation parameters, applying metadata, or completing other required configuration tasks — the Module Manager updates the module's status to reflect that progress. This dynamic updating means you always have an accurate, current picture of where each module stands. You do not need to remember which steps you have completed or keep a separate checklist; the Module Manager tracks it for you.

The progression of status states can be understood as a pipeline with a clear destination:

  • Empty: The module has been created but no configuration or content has been added. This is the starting state for every new module.
  • In Progress / Partially Configured: One or more setup steps have been completed, but the module is not yet ready for generation or authoring. The Module Manager will indicate what remains to be done.
  • Content-Ready: All required setup steps have been completed. The module is fully prepared for AI generation or further authoring work. This is the target state that the entire setup process is designed to reach.

The content-ready status is particularly significant because it is the gateway to the next phase of work. A module that has reached content-ready status can be submitted for AI generation, handed off for manual authoring, or advanced to the next stage of the production workflow. The Module Manager's status tracking ensures that modules do not move forward prematurely — a module must satisfy the requirements of each stage before its status advances.

This approach to status tracking protects content quality by making incomplete setup visible rather than invisible. If a required configuration step has been skipped, the module's status will reflect that, and the Module Manager will surface the missing action rather than allowing the module to proceed with gaps in its setup.

Guiding Users Through the Setup Process

The Module Manager is not simply a passive display of information — it actively guides users through the setup process. At each stage, the interface surfaces the necessary actions so users always know what to do next. This is a deliberate design choice: rather than requiring users to know in advance what every setup step is and in what order to perform them, the Module Manager makes the required next action visible and accessible from wherever you currently are.

Setup milestones are made visible within the manager, which significantly reduces the chance of accidentally skipping a required configuration step. For new users, this guidance is especially valuable because it removes the need to consult external documentation just to understand the correct sequence of actions. For experienced users, it provides a reliable confirmation that nothing has been missed, even when working quickly across multiple modules.

Consider a practical example: suppose you have created a new module and the Module Manager shows it in empty status. The interface will highlight or surface the action needed to move forward — perhaps prompting you to define the module's source content or configure its generation settings. Once you complete that step, the status updates and the next required action becomes visible. This step-by-step surfacing of actions continues until the module reaches content-ready status, at which point the setup workflow is complete.

This guided approach is consistent regardless of how the module was created. Whether you started from AI generation, added content from an existing folder on disk, or imported a module from a file or external repository, the Module Manager presents the same structured workflow path. Users do not need to learn different procedures for different creation methods — the interface normalizes the experience so that post-creation setup always follows the same logic.

Supporting All Three Creation Methods

PreseMaker supports three distinct methods for bringing a module into existence: generating one with AI, adding one from an existing folder on disk, and importing one from a file or connected repository. Each method has its own starting point and its own initial conditions, but once a module enters the Module Manager, all three are treated identically.

  • AI Generation: A module created through AI generation begins in the Module Manager as an empty or partially configured entry, ready to have its generation parameters defined and refined before the AI process runs.
  • Added from Disk: A module sourced from an existing folder on disk enters the Module Manager with its source content already associated, but may still require configuration steps — such as metadata or structural settings — before reaching content-ready status.
  • Imported from File or Repository: A module brought in through import may arrive with various levels of pre-existing configuration, but the Module Manager will identify any gaps and guide the user through completing the necessary steps.

The unifying principle is that the Module Manager normalizes the experience across all three methods. Post-creation steps are handled identically regardless of how the module originated. This is an important architectural decision because it means users do not need to develop separate mental models for working with AI-generated modules versus disk-sourced modules versus imported modules. The workflow is the same; only the starting conditions differ.

This normalization also enables something practically powerful: you can mix modules from different creation methods and manage them side by side within the same Module Manager interface without any difference in workflow. An AI-generated module and a disk-sourced module sitting next to each other in the Module Manager will follow the same status progression, respond to the same actions, and ultimately reach content-ready status through the same process. There is no second-class treatment for any creation method — all modules are equal within the manager once they have been created.

This design philosophy — consolidation, consistency, and active guidance — makes the Module Manager far more than a simple list or dashboard. It is the structural backbone of the module creation and setup process in PreseMaker, and mastering how it works is the first and most important step toward working efficiently with the platform as a whole.
