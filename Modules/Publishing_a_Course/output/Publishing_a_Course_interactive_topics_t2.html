Understanding Module HTML Index Pages

▶

Every module within a course built in PreseMaker is represented on the published website by a dedicated HTML file known as the module HTML index page. This file is the authoritative web presence for its module — it is what a learner actually encounters when they navigate to that module on the live site. Understanding what this file is, how it is created, and what role it plays is fundamental to understanding how PreseMaker translates authored content into a coherent, browsable course website.

The concept is straightforward in principle but rich in implication. A course is composed of multiple modules, and each module contains its own body of learning content. For that content to be accessible on the web, it must be represented by a file that a browser can open and render. The HTML index page is exactly that file — a standard HTML document that any modern web browser can open without plugins, special software, or additional configuration. Because it is plain HTML, it is universally compatible and immediately usable by learners on any device or platform.

What Is a Module HTML Index Page?

At its most basic level, a module HTML index page is a file automatically generated and associated with a specific module. It carries the module's name and identity, meaning the file is not a generic template shared across modules — each module has its own distinct index file. This one-to-one relationship between a module and its index file is deliberate and important: it keeps each module's content self-contained and independently accessible. A learner or instructor can navigate directly to a specific module's index page without having to pass through any other module's content.

Because it is a standard HTML file, it behaves exactly as any web page does. It can be bookmarked, linked to directly, opened in a browser tab, and rendered on any device that supports a web browser. There is no proprietary format to decode and no special viewer to install. This universality is one of the key practical advantages of the index page approach.

The association between a module and its index file is managed automatically by PreseMaker. Authors do not need to manually create or name these files — the system handles that relationship, ensuring the file's name and metadata correspond correctly to the module it represents. This automatic association means that when the module is updated, the system knows exactly which index file needs to be refreshed.

The Landing Page Role of the Index File

When a learner is browsing the course website and clicks on a link to a particular module, the destination of that click is the module's HTML index page. In web development terminology, a page that serves as the first point of entry for a section of a site is called a landing page, and the module index file fulfills exactly this role. It is the front door to the module's content area.

This landing page function means the index file has an orienting responsibility. A learner arriving at the index page should be able to understand what the module contains and how to engage with its content. The page presents the module's material in a structured, accessible way, giving the learner a clear picture of what they have entered. Rather than dropping a learner into an undifferentiated mass of content, the index page provides organization and context.

The landing page role also anchors the module within the broader course site hierarchy. Just as a building has a main entrance that connects it to the street and to a larger neighborhood, the index page connects the module to the overall course website. It is the point where the course's navigation system hands off control to the module's own content area. This positional role means the index page is not merely decorative or optional — it is a structural requirement for the module to function as part of the site.

How the Index Page Represents Module Content

The index page does not merely announce that a module exists — it actively surfaces the module's key content elements, giving learners an accurate and useful representation of what the module includes. Think of it as a window into the module: what appears on the index page reflects the actual substance of the module's authored content.

This representative function has a direct practical consequence for authors. Any content that is added to a module, removed from it, or modified within it should ultimately be reflected in the module's index page. If a new topic is added to the module, the index page should represent that addition. If a section is removed, it should no longer appear. The index page and the module's internal content must stay in sync, because the index page is what learners see — a mismatch between the two creates confusion and undermines trust in the course materials.

The index file acts as a bridge between the raw module content — which exists in PreseMaker's authoring environment — and the published website that learners access. The authoring environment is where content is created and organized; the index page is how that content is translated into a browsable, navigable web page. Without the index page performing this translation, the module's content would exist internally but would have no accessible web representation.

Consider a concrete example: suppose a module contains five learning topics, a quiz, and a set of downloadable resources. The module's HTML index page would represent all of these elements in an organized, linked format — learners can see what is available and navigate to any component directly. If the author later adds a sixth topic, publishing the module updates the index page to include that new topic alongside the original five. The index page thus always presents the module's current, complete content inventory to the learner.

Publishing Refreshes the HTML Index

The index page is not a static file that is created once and left alone. It is a generated file, meaning it is produced and reproduced by PreseMaker each time the publish feature is run. Every time an author publishes their course or a specific module, PreseMaker regenerates the HTML index files to incorporate the latest module content. This regeneration is what keeps the published site accurate and up to date.

The importance of this refresh cycle cannot be overstated. Without it, an author could make significant changes to a module — adding content, restructuring topics, removing outdated material — and those changes would exist in the authoring environment but would never appear on the live website. Learners would see an outdated version of the module, potentially missing new content or encountering links to content that has been removed. The publish-and-refresh cycle eliminates this problem by ensuring the index page is always regenerated from the current state of the module.

This mechanism also prevents a subtler problem: mismatched content. If part of a module is updated but the index page is not refreshed, the index page might link to resources that have changed or moved, producing broken links or inconsistent experiences. By regenerating the entire index page on each publish, PreseMaker ensures that what is described and linked on the index page matches what actually exists in the published module.

The practical workflow implication is clear: authors should publish their course after making meaningful changes to a module's content. The act of publishing is what makes changes real and visible on the live site. Authoring and publishing are distinct steps, and the index page refresh happens during the publishing step — not during authoring.

Index Pages Within the Site Structure

No module exists in isolation within a course. Each module is part of a larger course site that learners navigate as a whole. The module HTML index pages collectively form the navigable layer of the course website — each index page represents one module's content area, and together they make up the set of destinations a learner can visit within the course.

Each module's index page is linked from the course's main site navigation. This means that the top-level navigation of the course site — the menu or list of modules a learner sees when they first arrive — consists of links pointing to individual module index pages. When a learner selects a module from the course menu, they are following a link to that module's index page. This structure creates a clean, hierarchical site architecture: the course level connects to module index pages, and module index pages connect to individual content components within the module.

This architecture has an important implication for site coherence. If a module's index page is missing, malformed, or not properly linked from the navigation, that module becomes effectively unreachable — what site architects call an orphaned page. Learners browsing the course would have no way to find it through normal navigation. PreseMaker's automatic generation and linking of index pages during publishing is designed to prevent exactly this situation. By regenerating index pages and maintaining their links within the navigation structure, the system ensures that every module remains reachable and that the published site functions as a unified, coherent whole.

The following table summarizes the key characteristics and functions of a module HTML index page:

Characteristic Detail
File type Standard HTML file, viewable in any web browser without special software
Scope One index file per module; each is distinct and self-contained
Primary role Landing page — the first page a learner sees when navigating to a module
Content relationship Reflects the current content of the module; must stay in sync with module changes
Generation method Automatically regenerated by PreseMaker each time the publish feature is run
Site structure role Linked from course navigation; prevents modules from becoming orphaned or unreachable

In summary, the module HTML index page is the essential web-facing representation of a module. It is automatically managed, universally compatible, and regenerated on every publish to stay accurate. It serves as the entry point for learners, the bridge between authored content and the live site, and a structural node within the course website's navigation hierarchy. A well-functioning set of index pages is what transforms a collection of authored modules into a coherent, navigable course website.
