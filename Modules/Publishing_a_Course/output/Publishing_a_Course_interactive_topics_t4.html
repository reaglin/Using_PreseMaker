Assembling Modules into a Course Website

▶

Building a complete course website from a collection of individual modules is one of the most important final steps in the course development workflow. When you create a course using PreseMaker, your work naturally divides into discrete modules — each covering a distinct subject area, unit, or learning objective. Those modules are powerful on their own, but learners need a unified, navigable experience that lets them move through the entire course without confusion or dead ends. The assembly process is what transforms a collection of separate modules into a single, coherent, browsable website. Understanding how this process works from start to finish — before touching a single button — is the best way to avoid common mistakes and produce a polished result.

The assembly process follows a clear sequence of events. First, PreseMaker refreshes each module's HTML index file to reflect the most current saved content. Then it compiles those refreshed index files into a unified site structure, generating the navigation links that connect every module together. The end product is a fully linked website that learners can open in any browser and explore from beginning to end. Each of the major concepts below builds on this overall picture, so keep the sequence in mind as you work through the details.

The Role of Each Module's HTML Index File

Every module in a PreseMaker course has an HTML index file at its core. Think of this file as the front door to that module — it is the very first page a learner sees when they navigate into that section of the course. The index file does not contain all of the module's content itself; instead, it acts as an organized entry point that links outward to that module's individual lessons, topics, sub-topics, media assets, and any other resources the module contains.

Because the index file is the hub from which all of a module's content radiates, keeping it accurate and current is critically important. If a lesson is added, renamed, reordered, or removed, the index file must reflect that change before learners encounter it. An outdated index file can send learners to content that no longer exists, display an old title for a lesson that has been revised, or omit new content entirely — all of which undermine the learning experience and erode trust in the course.

In practical terms, the index file holds information such as:

  • Module title and description — the human-readable name and summary that appears when learners first enter the module.
  • Links to individual lessons or topics — ordered references to every piece of content within the module, typically rendered as a list or menu.
  • Links to downloadable assets — where applicable, references to PDFs, worksheets, or other supporting files attached to the module.
  • Metadata used by the navigation system — behind-the-scenes information PreseMaker uses to integrate the module into the broader course site.

Because the index file serves both learners and PreseMaker's own assembly engine, any inconsistency between the index file and the actual module content creates problems at two levels: the learner-facing experience breaks down, and the automated assembly process may produce incorrect navigation links or even fail to include the module in the final site structure altogether.

How Publishing Refreshes Module Content

One of PreseMaker's most important behaviors during the assembly process is the automatic refresh it performs on every module's HTML index file at the moment you initiate a publish action. This refresh cycle is what keeps the assembled website synchronized with the work you have done inside each module.

Here is what happens step by step during a refresh:

  • PreseMaker reads the current saved state of each module — every lesson, every topic title, every asset reference, and every piece of structural metadata.
  • It rewrites the module's HTML index file to match that current state precisely, overwriting whatever the index file contained before.
  • It validates that all internal links within the module (lessons linking to sub-topics, topics linking to media, and so on) are still intact and pointing to the correct files.
  • Once all module index files have been refreshed, PreseMaker moves on to compile them into the top-level site structure.

The practical implication of this behavior is significant: the published website always represents the state of your modules at the exact moment you pressed publish. Changes you make after publishing are not visible to learners until you publish again. Conversely, changes you made before publishing — even if you made them days earlier — will be captured correctly by the refresh cycle. This makes the publish action the definitive checkpoint in your workflow: everything before it is draft, and everything after it is live.

This also means you should save all your work inside each module before initiating the publish process. PreseMaker reads from saved files. Any unsaved edits sitting in an open editor pane will not be included in the refresh, and the resulting website will not reflect those changes. A reliable habit is to close and save every open module editor before publishing, then verify the output.

Using PreseMaker's Publish Feature to Build the Site

The publish feature is the central control that drives the entire assembly process. Locating it correctly within PreseMaker's interface is the necessary first step — the exact location depends on the version of PreseMaker you are using, but it is typically found in the main toolbar, the File menu, or a dedicated Course panel. If you are working with PreseMaker for the first time, take a moment to explore the interface and identify the publish option before you begin, so you are not searching for it mid-process.

Once you initiate publishing, PreseMaker proceeds through its sequence automatically. The stages of the publish process are:

Stage What PreseMaker Does What You Should Know
1. Pre-publish validation Checks that all modules are saved and that required metadata is present. Errors here indicate unsaved work or missing module information that must be corrected before proceeding.
2. Index refresh Rewrites every module's HTML index file based on current saved content. This is automatic; no manual action is needed, but it may take a moment for large courses.
3. Site structure compilation Combines all refreshed index files into the top-level site, generating the course homepage and inter-module navigation. The order of modules in the compiled site is determined by the course structure you defined, not alphabetical file order.
4. Asset copying Copies all referenced media, documents, and stylesheets into the output directory. If any asset file is missing from its expected location, the publish may complete but the site will have broken links.
5. Output delivery Writes the completed website to the designated output folder. The output folder contains everything needed to deploy the site — all HTML, CSS, JavaScript, and media files are self-contained.

When the publish process completes successfully, the output folder contains a fully self-contained website. You can open the top-level index.html file from that folder in any modern browser to preview the site locally before distributing it to learners. If you plan to host the site on a web server or learning management system, you would upload the entire contents of the output folder to your hosting environment.

A common mistake during this step is publishing to an incorrect output directory or overwriting a live site with a version that has not been fully reviewed. Establishing a clear folder convention — for example, keeping a draft output folder for preview and a separate live output folder for deployment — prevents accidental overwrites and gives you a safe space to verify the assembled site before learners see it.

Ensuring a Cohesive Navigation Structure

One of the most valuable things PreseMaker does during assembly is generate navigation links automatically. Rather than requiring you to manually write HTML links between every module, PreseMaker reads the course structure you have defined — the order of modules, the hierarchy of lessons within each module, and the relationships between them — and produces a consistent navigation system that carries learners through the course from beginning to end.

Automatic generation, however, does not mean guaranteed correctness. The navigation PreseMaker produces is only as accurate as the course structure you defined. If modules are in the wrong order in your course settings, they will appear in that wrong order in the navigation. If a module was accidentally excluded from the course structure, it will be absent from the navigation even though its content files exist. This is why reviewing the assembled site after every publish is an essential part of the workflow, not an optional final check.

When reviewing the assembled site's navigation, work through the following checklist:

  • Module sequence — Open the course homepage and confirm that all modules appear in the intended order. The sequence should match your course design document or syllabus.
  • Module accessibility — Click through to every module to confirm its index page loads without errors and displays the correct title and lesson list.
  • Inter-module links — At the end of one module, verify that the navigation correctly points to the next module. At the beginning of a module, verify the back link points to the previous module or the course homepage as appropriate.
  • Lesson-level navigation — Within at least one or two modules, click through individual lessons to confirm the forward and backward navigation within the module works correctly.
  • Asset links — If modules include downloadable files or embedded media, verify that those assets load correctly in the assembled site.

Consistent, well-functioning navigation has a direct impact on learner experience that is easy to underestimate. When navigation works correctly, learners focus entirely on the content — they are not thinking about where they are in the course or how to get to the next section. When navigation is broken or confusing, it interrupts the learning process, generates support requests, and can cause learners to miss content entirely because they cannot find it. Investing a few minutes in a thorough navigation review after every publish is one of the highest-value quality-assurance steps in the entire course production process.

If you discover navigation issues during your review, the fix almost always involves correcting the course structure settings within PreseMaker — reordering modules, adding a missing module, or correcting a title — and then publishing again. Because the publish process refreshes everything from the source, a corrected publish will overwrite the previous output with an accurate version.
