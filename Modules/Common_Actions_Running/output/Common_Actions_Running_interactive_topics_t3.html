Running Multiple Tasks Together in One Step

▶

When building a course, instructors routinely need to produce several different assets for each module — a study document, a quiz, a slide deck, and more. Traditionally, each of those outputs would be generated separately, requiring the instructor to navigate to a different tool or menu, configure options, trigger the generation, wait for the result, and then repeat the entire process for the next deliverable. The Common Actions Hub is designed to eliminate that repetitive cycle by consolidating all of those generation tasks into a single, centralized workspace where everything can be configured and launched together in one operation.

Understanding how the hub works — and why it is structured the way it is — helps instructors get the most out of it. The sections below walk through each dimension of the feature in depth, from what the hub actually is, to how settings are preserved across sessions.

What the Common Actions Hub Is

The Common Actions Hub is a dedicated interface that surfaces all of the major generation tasks available for a given module in one place. Rather than scattering quiz creation in one menu, document generation in another, and presentation building somewhere else entirely, the hub gathers them together so an instructor can see all available actions at a glance.

A critical design principle of the hub is that it is scoped per module. This means that when you open the hub for Module 3, every task you see, every setting you configure, and every output that gets generated is tied specifically to the content of Module 3. You are not looking at a global tool that operates on the whole course at once; you are looking at a focused workspace for a single module's deliverables. This scoping ensures that generated content is always contextually accurate — a quiz built from Module 3 draws only on Module 3 material, not on content from other parts of the course.

The tasks available within the hub typically include, but are not limited to:

  • Document generation — producing a formatted study guide, notes document, or reading resource derived from the module's content.
  • Quiz creation — generating assessment questions aligned to the module's learning objectives and subject matter.
  • Presentation building — assembling a slide deck that covers the module's key concepts in a visual, structured format.

Because all of these tasks live in the same hub, an instructor never has to leave the workspace to move from one generation task to another. This centralization directly reduces the cognitive load and the time spent navigating between different tools or menus — a small saving per task that compounds significantly across a full course with many modules.

Selecting and Configuring Tasks Before Running

Before any generation takes place, the hub requires the instructor to make two deliberate decisions for each task: whether to include it in the upcoming run, and how it should be configured. These two steps — selection and configuration — happen before the batch is launched, ensuring that the system has everything it needs to produce the right output without interrupting the instructor mid-run to ask clarifying questions.

Selection works through individual toggles. Each task in the hub has an on/off control. If an instructor only needs a quiz and a document for a particular module but does not need a slide deck right now, they simply leave the presentation task toggled off. Only the tasks that are switched on will be included when the run is initiated. This gives instructors precise control over what gets generated — nothing is produced that was not explicitly requested.

Configuration happens per task and allows the instructor to specify the details of what they want. For a quiz, configuration might include the number of questions, the question types (multiple choice, true/false, short answer), and the difficulty level. For a document, it might include the format, the level of detail, or whether to include a summary section. For a presentation, it might cover the number of slides or the visual structure. Each task's configuration options are set independently, so the quiz can be configured for ten challenging questions while the document is configured for a concise overview — all within the same session, before the run begins.

The practical implication is important: only tasks that have been both selected and fully configured will be included in the batch run. A task that is toggled on but left at default settings will still run using those defaults, and a task that is toggled off entirely will be skipped regardless of how it was previously configured. This design prevents accidental generation of unwanted outputs and ensures the instructor is always in control of the final set of deliverables.

Running All Selected Tasks Together in One Step

Once the instructor has selected the tasks they want and configured each one, they initiate the batch run with a single command. From that point forward, the system takes over. It processes each selected task in sequence, one after another, without requiring any further input from the instructor. The quiz is generated, then the document, then the presentation — or in whatever order the system processes them — all as part of a single uninterrupted operation.

This is the defining efficiency of the hub. Without batch execution, generating three deliverables would require the instructor to:

  • Navigate to the quiz tool, configure it, trigger generation, and wait for completion.
  • Navigate to the document tool, configure it, trigger generation, and wait for completion.
  • Navigate to the presentation tool, configure it, trigger generation, and wait for completion.

Each of those steps involves not just the time for the generation itself, but the overhead of navigation, re-orientation, and re-entry of settings. With the hub's batch execution, all three tasks are configured once in one place and then processed in a single run. The instructor can step away while the system works through the queue, returning only when all outputs are ready.

This approach is especially valuable in scenarios where an instructor needs to produce a full set of module deliverables before a course goes live, or when updating a module requires regenerating all associated assets at once. Instead of spending time managing each generation task individually, the instructor invests that time upfront in configuration — where their expertise actually matters — and then lets the system handle execution.

Efficiency Gains from Batching Generation Tasks

The time savings from batching are real and compounding. Consider a course with twelve modules, each requiring a quiz, a study document, and a presentation. Generating those assets individually would mean thirty-six separate generation workflows. Even if each workflow takes only a few minutes of active instructor attention, the total adds up quickly — and that estimate does not account for the mental switching cost of repeatedly shifting context between different tools.

Batching reduces that overhead in two ways:

  • Eliminating repetitive setup: Configuration happens once per module session, not once per task. An instructor setting up three tasks in the hub completes one setup workflow instead of three separate ones.
  • Eliminating repetitive execution: One run command replaces three separate trigger actions, three separate waits, and three separate confirmations that each task completed successfully.

Beyond time, there is a consistency benefit. When all of a module's deliverables are generated from the same content in the same pass, they share a common source. The quiz questions, the document explanations, and the presentation slides all draw from the same module material at the same point in time. This reduces the risk that assets become misaligned — for example, a quiz that reflects an older version of the content because it was regenerated separately at a different time. Batching keeps all outputs in sync with each other and with the current state of the module.

At a broader level, the course production workflow becomes noticeably faster and more streamlined. Instructors who adopt batch generation as a standard practice find that the time from "module content is ready" to "all module assets are published" shrinks considerably, freeing up time for higher-value work like reviewing outputs, refining content, and responding to learner needs.

How Common Actions Remembers Settings Per Course

One of the most practical features of the hub is its ability to remember the configuration settings that were used for previous runs. Rather than requiring instructors to re-enter their preferences every time they return to a module, the hub stores those settings and makes them available on the next visit. When an instructor opens the hub for a module they have worked with before, their prior selections and configurations are already in place, ready to use.

This memory feature operates at the course level, meaning that saved settings for one course do not interfere with settings for another course. Each course maintains its own record of what was configured for each module. This is particularly useful for courses that follow a consistent structure — for example, a course where every module is expected to have a ten-question multiple-choice quiz and a two-page summary document. Once that configuration is set up and run for the first module, it persists as the default for subsequent modules, so the instructor only needs to make adjustments rather than starting from scratch each time.

Saved settings also make it easier to re-run tasks when module content changes. If an instructor updates the material in a module and needs to regenerate the quiz and document to reflect those changes, they can open the hub, confirm that the saved settings still match their intent, and immediately launch a new run without reconfiguring anything. The system remembers the decisions that were already made.

Importantly, saved settings are never locked in. Instructors can adjust any saved configuration at any time before initiating a new run. If a particular module requires a longer quiz than usual, or if a presentation needs more slides to cover additional content, those adjustments can be made on the spot. The saved settings serve as a starting point — a convenience that preserves prior work — not as a constraint that limits flexibility.
