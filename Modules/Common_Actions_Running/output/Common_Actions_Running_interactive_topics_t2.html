Selecting and Configuring Generation Tasks

▶

When building course content efficiently, one of the most powerful capabilities available to instructors is the ability to generate multiple types of learning materials from a single, coordinated interface. Rather than producing documents, quizzes, and presentations through separate, disconnected workflows, the Common Actions Hub consolidates these generation tasks into one place, allowing instructors to select exactly what they need, configure each task to match their instructional intent, and run everything together in a single operation. Understanding how to navigate this process — from opening the hub to fine-tuning per-task settings — is essential to making content generation work reliably and purposefully.

Accessing the Common Actions Hub

The Common Actions Hub is scoped at the module level, which is an important architectural detail. This means every module within a course has its own dedicated Common Actions area, independent from other modules. When you open the hub for a given module, you are working exclusively within the context of that module's content — its topics, its structure, and its associated settings.

Opening the hub presents a unified interface where all available generation task options are displayed together and ready for interaction. You do not need to navigate between separate menus or configuration screens to see what is available. Everything is surfaced in one place, making it straightforward to survey your options, make selections, and proceed to configuration without losing context.

Because the hub is module-specific, instructors working across a course with multiple modules will interact with the Common Actions Hub separately for each module. This design ensures that the configuration choices made for one module do not inadvertently affect another, and it allows each module to carry its own tailored generation profile.

Understanding the Available Generation Tasks

The hub offers several distinct generation task types, each producing a different kind of learning artifact. Understanding what each task produces helps instructors make informed decisions about which tasks serve their current instructional goals.

  • Document per topic: This task generates a written content document that is organized and broken down by the individual topics within the module. Rather than producing one undifferentiated block of text, the output mirrors the module's topic structure, making it easier for learners to read and reference specific sections. This is well-suited for use as reading material, study guides, or supplementary handouts.
  • Multiple-choice quiz: This task creates assessment questions drawn from the module's content. The questions are designed to test comprehension and recall of key concepts, and the format follows a standard multiple-choice structure with a question stem and selectable answer options. This is useful for formative assessment, end-of-module checks, or practice activities.
  • Presentation: This task produces a slide-based format appropriate for both instructor-led classroom delivery and self-paced learner review. The content is restructured into a visual, slide-oriented layout that emphasizes key points rather than comprehensive prose. This is particularly valuable when an instructor needs to deliver content verbally and wants supporting visuals, or when a learner-facing slide deck is part of the course design.

A critical principle here is that instructors are not required to select all available tasks. The hub does not impose an all-or-nothing approach. If a particular module only calls for a quiz and a document — with no need for a presentation — the instructor selects only those two tasks and leaves the presentation task aside. This flexibility ensures that generation work is purposeful rather than formulaic.

Selecting Which Tasks to Include

Within the hub interface, each available generation task can be individually toggled or selected. The selection mechanism allows for granular control: an instructor might select only the document task for a module that is purely informational, or they might select all three tasks for a module that will be delivered live, assessed formally, and made available for independent study.

There is no minimum beyond one task and no requirement to combine tasks in any particular way. Instructors can run as few as one task at a time or group multiple tasks to execute together in a single operation. Running tasks together is generally more efficient than executing them one by one, and it ensures that all selected outputs are generated from the same content state at the same time.

It is important to understand that selection is a prerequisite to configuration. A task must be selected before its configurable settings become accessible and editable. This sequencing is intentional — it prevents instructors from spending time adjusting settings for tasks they have not yet committed to including. Once a task is selected, its configuration options become available and the instructor can proceed to tailor that task's behavior.

Configuring Settings for Each Task

After selecting the tasks to include, each selected task exposes its own set of configurable parameters. These parameters vary by task type and allow instructors to control how the generated content is shaped, structured, and scoped. Configuration happens per task, meaning the settings adjusted for the quiz task are entirely separate from those adjusted for the document or presentation task.

Examples of configurable parameters by task type include:

  • Document per topic: Instructors may be able to adjust depth of content, tone, or the level of detail included in explanations — for example, whether the document should read as an introductory overview or a comprehensive deep-dive into each topic.
  • Multiple-choice quiz: Key parameters typically include the number of questions to generate, the difficulty calibration, and — importantly — whether questions should be generated per topic individually or as a single pooled quiz across the module. This granularity setting is discussed further below.
  • Presentation: Settings may govern the number of slides, the density of content per slide, and whether the output is optimized for instructor delivery or self-paced learner consumption.

The value of configuring tasks before running them cannot be overstated. When settings are aligned with instructional intent before generation begins, the outputs are far more likely to be usable as-is or with minimal revision. Relying on post-generation editing to fix misaligned outputs — such as a quiz with too many questions or a document that is too shallow — is less efficient and can introduce inconsistency across a course.

How Common Actions Remembers Settings Per Course

One of the more practically useful behaviors of the Common Actions Hub is its ability to recall previously configured settings. When an instructor has configured and run tasks for a module in a previous session, the settings used in that session are automatically stored and recalled when the instructor returns to Common Actions for the same course.

This persistence is scoped per course, not globally across all courses. This means that the configuration profile maintained for one course — perhaps a technical training course that uses long-form documents and detailed quizzes — does not interfere with the profile maintained for a different course that might favor concise slides and shorter assessments. Each course carries its own remembered configuration, reflecting the distinct instructional context of that course.

The following table summarizes how settings persistence works across different scenarios:

Scenario Settings Recalled? Notes
Returning to the same course, same module Yes Previously saved settings are automatically loaded for that module.
Returning to the same course, different module Yes (course-level defaults) Settings last saved within the course context are applied as a starting point.
Opening a different course No (separate profile) The other course maintains its own independent configuration profile.
First use of Common Actions for a course No No prior settings exist; defaults are presented for the instructor to configure.

Even though settings are remembered automatically, instructors should always review the recalled settings before initiating a run. Instructional needs evolve — a module that previously warranted a 10-question quiz may now be restructured to cover fewer topics, making a shorter quiz more appropriate. Treating remembered settings as a starting point for review, rather than as a final configuration, is a sound practice that prevents outdated settings from producing misaligned outputs.

Tailoring Quiz Generation with Per-Topic Settings

Among the available configuration options, the quiz task's granularity setting is one of the most consequential. By default or by choice, quizzes can be generated either as a single combined set of questions drawn from across the entire module, or as a separate, focused set of questions generated for each individual topic within the module.

Choosing to generate quizzes per topic means that if a module contains, for example, five topics, five distinct question sets are produced — each one scoped tightly to the content of its corresponding topic. This approach carries several practical advantages:

  • Improved reliability of questions: When the question generation is focused on a single, well-defined topic rather than attempting to draw from a broad and varied module, the resulting questions tend to be more precise, clearly worded, and directly aligned with the content. The risk of generating vague or tangentially related questions is reduced significantly.
  • Instructional flexibility: Per-topic quizzes can be deployed at different points in the learning sequence — for instance, immediately after each topic is taught — rather than only at the end of a module. This supports formative assessment strategies and allows learners to check their understanding incrementally.
  • Easier review and editing: When questions are organized by topic, reviewing and editing them is more manageable. An instructor can evaluate each topic's question set in context, rather than sifting through a mixed pool of questions from across an entire module.

This granularity setting is configured within the quiz task's options before the run is initiated. Like all other task settings, it is accessible only after the quiz task has been selected in the hub. Instructors working on content-heavy modules with several distinct topics will generally find the per-topic approach yields higher quality outputs, while those with simpler, tightly unified modules may find a combined quiz entirely appropriate.

Taken together, the process of selecting tasks, configuring their settings, and leveraging the hub's memory of course-specific configurations gives instructors meaningful control over what gets generated and how. The Common Actions Hub is not simply a trigger for automated content creation — it is a configuration layer that, when used thoughtfully, produces learning materials closely aligned with the instructor's design intent from the very first run.
