Introduction to the Common Actions Hub

▶

When building out a course module, instructors typically need to produce several different types of learning assets: written documents, assessments, presentations, and more. Without a centralized place to manage these tasks, the process can become fragmented — requiring an instructor to navigate to different areas of the platform, reconfigure settings each time, and generate each asset separately. The Common Actions Hub is the solution to this fragmentation. It provides a single, unified interface where instructors can configure and trigger multiple content generation tasks at once, all within the context of a specific module.

Understanding what the Common Actions Hub is, why it exists, and how it fits into the broader instructor workflow is the foundation for using it effectively. Each of these dimensions is worth exploring in depth.

What Is the Common Actions Hub?

The Common Actions Hub is a dedicated interface within the platform that brings together the most frequently needed content generation tasks for a module. Rather than scattering these tasks across different menus or tool areas, the hub collects them in one place and presents them as a coordinated set of actions an instructor can take together.

A critical design characteristic of the hub is that it is scoped per module. This means that when you open the Common Actions Hub, you are always opening it in relation to a specific module — its topics, its settings, its content structure. You are not working in a global tool that operates independently of your course content. Every task you configure and every asset you generate is anchored to that module. This scoping ensures that the outputs are always contextually relevant and aligned to the right content.

For example, if your course has five modules, you will work through the Common Actions Hub five times — once per module — as you build out the course. Each session in the hub is its own contained workflow for that module's assets.

The types of tasks the hub brings together include, but are not limited to:

  • Document generation per topic — producing written learning documents that cover the topics defined within the module.
  • Quiz creation — generating multiple-choice or other question-based assessments tied to the module's content.
  • Presentation building — creating slide-based presentations derived from the module's topics and subtopics.

By gathering these tasks under one roof, the hub eliminates the need to hunt for individual tools and re-establish context each time you want to generate a new type of asset.

Purpose of the Common Actions Hub

The hub exists to solve a practical problem: content creation for a module involves many moving parts, and doing them one at a time — in isolation — is slow, error-prone, and inconsistent. The Common Actions Hub addresses this by serving three core purposes.

First, it reduces the number of steps required to produce a full set of learning materials. Instead of navigating to a document tool, generating a document, then navigating to a quiz tool, configuring it, generating a quiz, and so on, the instructor performs all configuration in one place and triggers all generation in one action.

Second, it ensures alignment across all generated assets. Because every task is configured and run against the same module — with the same content structure and settings active at that moment — the outputs are coherent with one another. A document, a quiz, and a presentation generated together through the hub will all reflect the same topics, the same scope, and the same module state. This is harder to guarantee when assets are generated at different times using separate tools.

Third, it supports a batch-style approach to content generation. Rather than a one-task-at-a-time workflow, the hub encourages instructors to think about what a module needs holistically, configure everything up front, and then produce all the needed assets in one pass. This mirrors how experienced instructors naturally think about module design — as a complete package of materials rather than a series of disconnected outputs.

Where Common Actions Fits in the Instructor Workflow

The Common Actions Hub is not a standalone tool or an external add-on — it is embedded directly in the standard module workflow. Instructors encounter it as a natural step after setting up a module's content structure. The placement is deliberate: the hub comes after content has been defined but before final assets are delivered to learners, positioning it as the bridge between content setup and content delivery.

This positioning has an important practical implication. Because instructors access the hub after the module's topics and settings are in place, all task configurations within the hub can be reviewed and adjusted before any generation is triggered. Nothing is produced automatically or prematurely. The instructor retains full control over what gets generated and how, right up until the moment they choose to run the tasks.

The per-module nature of the hub also means the workflow scales naturally as a course grows. An instructor building a ten-module course works through the hub ten times — once for each module — rather than trying to manage all modules simultaneously. This keeps the work focused and manageable at each stage.

To illustrate how the hub sits within the broader workflow, consider the following sequence:

  • The instructor creates a module and defines its topics and subtopics.
  • The instructor opens the Common Actions Hub for that module.
  • The instructor reviews the available tasks and selects those needed for this module (for example, a document and a quiz, but not a presentation).
  • Each selected task is configured individually — specifying things like question count for a quiz or formatting preferences for a document.
  • With all configurations set, the instructor triggers all selected tasks together in a single step.
  • The generated assets are produced and become available as part of the module's resources.
  • The instructor moves on to the next module and repeats the process.

Types of Tasks Available in the Hub

The hub presents instructors with a set of task options, each representing a different type of learning asset. Instructors are not required to run every task — the design is flexible, allowing you to select only the tasks that are relevant to a given module's needs.

The following table summarizes the common task types available in the hub and what each produces:

Task Output Typical Use
Generate Document per Topic Written learning document for each topic in the module Providing learners with reading material that covers each topic in depth
Create Multiple-Choice Quiz A question-based assessment tied to the module's content Testing learner comprehension and recall after completing the module
Produce Presentation A slide-based presentation derived from the module's topics Supporting live instruction or providing a visual summary of the module

Each task can be individually configured before generation. For a quiz, this might mean setting the number of questions or specifying the difficulty level. For a document, it might mean choosing the level of detail or the tone. These configurations are applied per task, giving instructors precise control over each asset type even when running all tasks together.

Running Tasks Together in One Step

The defining feature of the Common Actions Hub — the capability that most directly delivers its efficiency benefit — is the ability to run all selected and configured tasks together with a single action. Once an instructor has selected which tasks to include and has applied the relevant configuration to each, they trigger the entire batch at once rather than executing each task sequentially on its own.

This matters for several reasons. Most obviously, it saves time. Generating three asset types one at a time requires three separate triggering actions, three waiting periods, and three separate moments of navigating to the next task. Running them together collapses this into a single action and a single wait.

More subtly, running tasks together guarantees consistency. When assets are generated at different times — even within the same platform — there is always a risk that something changes between runs: a topic gets renamed, a setting is adjusted, or the module content is updated. Because the Common Actions Hub runs all tasks against the same module state at the same moment, all outputs are guaranteed to reflect the same version of the content. There is no risk of a quiz being generated from a slightly different version of the module than the document it is meant to accompany.

Finally, the batch approach encourages a more disciplined workflow. By requiring instructors to configure everything before triggering generation, the hub naturally promotes upfront planning. Instructors consider all their asset needs for a module at once, make deliberate choices about what to generate and how, and then commit to those choices together. This is a more thoughtful and less reactive approach than generating assets ad hoc as needs arise, and it tends to produce a more cohesive set of learning materials as a result.
