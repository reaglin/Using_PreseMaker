Entering Your API Key in PreseMaker Settings

▶

Connecting PreseMaker to an AI provider requires one straightforward configuration step: entering your API key in the application's Settings screen. Because PreseMaker is a single-user desktop application, there is no account login or online registration process to navigate — you simply open the app, go to Settings, paste your key, and save. Once that key is in place, PreseMaker can communicate directly with your chosen AI provider every time you generate content. This guide walks through each part of that process in detail, from finding the right screen to understanding how your key is protected after it is saved.

Navigating to the PreseMaker Settings Screen

When you launch PreseMaker, the main window gives you immediate access to the Settings area without requiring any sign-in. Look for one of the following entry points, depending on your version and operating system:

  • A gear icon displayed in the toolbar or in a corner of the main interface — this is the most common shortcut to Settings.
  • A Settings or Preferences option inside the main menu (for example, under a menu labelled File, Edit, or the application name on macOS).
  • A dedicated Settings button visible directly on the main window or welcome screen.

Once you click any of these entry points, the Settings screen opens. Inside Settings, locate the section labelled AI Providers or API Keys. This section is specifically dedicated to managing connections to external AI services and is where all provider configuration options are grouped together. You do not need to navigate through multiple sub-menus — all provider fields are visible in one place within that section.

Every provider has its own dedicated field. You can fill in keys for as many providers as you like — PreseMaker supports multiple active keys simultaneously. However, each key must be entered in the field that matches the provider it came from. An OpenAI key entered in the Anthropic field, for example, will not work and will produce an error when you first attempt to generate content. Identify which provider issued your key, locate that provider's field on the screen, and enter the key only there.

Entering the API Key Correctly

API keys are long, case-sensitive strings that are easy to mistype. The safest approach is always to copy and paste rather than type the key manually. Here is the recommended process:

  • Open your AI provider's website and sign in to your account dashboard. For Anthropic this is console.anthropic.com, for OpenAI it is platform.openai.com, for Google it is aistudio.google.com, and for Mistral it is console.mistral.ai.
  • Navigate to the API Keys section of that dashboard and click the button that reveals or copies your key. Some providers display the full key only once, so copy it immediately.
  • Switch back to PreseMaker Settings and click inside the input field for that provider to make sure it is focused.
  • Paste the key using Ctrl+V (Windows / Linux) or Cmd+V (macOS).

After pasting, take a moment to inspect the field visually. Confirm that:

  • The key begins and ends correctly — most keys start with a recognisable prefix (for example, OpenAI keys begin with sk-).
  • There are no leading or trailing spaces. These can be introduced if you accidentally selected a space before or after the key text when copying.
  • There are no line breaks inside the key. If your browser wrapped the key across two lines in the dashboard, pasting may insert a hidden newline character that breaks authentication.

If you are uncertain whether invisible characters were introduced, clear the field entirely, return to the provider dashboard to copy the key again, and paste it fresh.

Saving and Confirming the API Key Entry

After pasting and checking the key, you must explicitly save your entry. Look for a button labelled Save, Apply, or an equivalent confirmation control within the Settings screen. Clicking that button writes the key to PreseMaker's local storage. A few important points about this step:

  • The key is stored as soon as you confirm — there is no progress indicator or connection test to wait for at this stage.
  • PreseMaker does not display a separate "key verified" or "connection successful" banner after saving. The absence of an error message is normal — it simply means the key has been stored.
  • The key is exercised for the first time when you actually use an AI feature, such as generating slide content. If there is a problem with the key — it was entered incorrectly, has been revoked, or lacks the required permissions — PreseMaker will surface an error at that moment. The error will typically give you options to open Settings to correct the key, add a new key, or view the log for more technical detail.

Understanding Local Encryption of Your API Key

A key concern for many users is security: where does PreseMaker store the API key, and could it be accessed by third parties? PreseMaker addresses this by encrypting your API key locally on your device before storing it. This means:

  • The key is never transmitted to PreseMaker's servers. It remains entirely on the machine where you installed the application.
  • When you use an AI feature, PreseMaker decrypts the key in memory and uses it to make a request directly to your AI provider — the request goes from your device to, for example, Anthropic's servers, without passing through any PreseMaker infrastructure.
  • Because storage is local and tied to your installation, reinstalling PreseMaker or moving to a new device will result in your key being absent from the new installation. You will need to return to Settings and enter the key again. This is expected behaviour, not a bug — keep a secure copy of your API key (such as in a password manager) so you can retrieve it easily when needed.

Troubleshooting Common Key Entry Issues

If you attempt to generate content after saving your key and receive an authentication or connection error, work through the following checks systematically:

  • Wrong provider field: Return to Settings and verify that the key is in the field labelled for the correct provider. API keys are provider-specific tokens — an Anthropic key cannot authenticate a request to OpenAI, and vice versa. If you see a key in the wrong field, clear it, locate the correct field, and paste it there.
  • Expired or revoked key: Log in to your provider's dashboard and confirm that the key still appears as active. Providers sometimes automatically revoke keys that have not been used, that have exceeded a spending limit, or that the account owner manually deleted. If the key is inactive, generate a new one from the dashboard and enter it in PreseMaker.
  • Hidden characters or whitespace: This is the most common cause of a key that looks correct but fails to authenticate. To eliminate this possibility, click inside the provider's key field in PreseMaker Settings, select all the text in the field (Ctrl+A or Cmd+A), delete it, then return to your provider dashboard, copy the key again carefully, and paste it into the now-empty field before saving. Even one extra space at the end of the key will cause authentication to fail.
  • Insufficient permissions on the key: Some providers allow you to create restricted keys that only have access to certain models or API endpoints. If your key was created with restrictions that exclude the model PreseMaker is trying to use, the provider will reject the request. Check the key's permission settings in your provider dashboard and ensure it has access to the relevant models.
  • No internet connection: Although the key itself is stored locally, every AI generation request requires an active internet connection to reach the provider. Confirm your device is online before assuming the key configuration is faulty.

By following these steps carefully — copying rather than typing, pasting into the correct field, saving explicitly, and understanding that verification happens on first use — you will have your AI provider connected to PreseMaker quickly and reliably. The local encryption model means your credentials stay on your device, giving you both the convenience of a one-time setup and the assurance that your key is not exposed to external services beyond the AI provider itself.
