Monitoring Live Batch Progress

▶

When you launch a batch generation run in Course Manager, you don't simply click a button and wait in the dark. A dedicated live progress panel immediately becomes the central hub for everything happening during the run. Understanding how to read and interpret every element of that panel — from individual module status lines to the overall completion counter — gives you full situational awareness throughout the process, no matter how large or complex the batch may be.

The live progress panel is displayed prominently within the Course Manager interface the moment a batch run begins. Rather than scattering status information across multiple screens or requiring you to open each module individually to check on it, the panel consolidates the real-time state of every selected module into a single, readable view. Nothing is hidden or tucked behind a secondary menu. Crucially, the panel updates automatically and continuously — there is no need to manually refresh the page or click a reload button. What you see on screen always reflects the current, live state of the batch.

This design matters in practice because batch runs can involve dozens of modules running sequentially, and instructors frequently need to step away briefly, answer a message, or attend to something else. When they return, a single glance at the panel immediately re-orients them: how far along is the batch, which module is active right now, and has anything gone wrong.

Per-Module Status Indicators

Each module in the batch has its own status line within the panel, and that line is far more informative than a simple "running / done" toggle. The status line provides granular progress information at the topic level. For example, while a module is being generated you will see an indicator reading something like Topic 3 of 7, updating as each successive topic is completed. This means that even for a module with many topics — one that will take several minutes to finish — the status line shows visible, continuous movement. You are never left wondering whether the system has stalled or is silently making progress.

Beyond the topic-level counter, each module's status line carries one of several discrete indicators at any given moment:

  • In Progress: This indicator signals that content is actively being generated for that module right now. Only one module carries this indicator at a time during a sequential batch run. It is the "currently active" signal.
  • Completed: This indicator confirms that the module's content has been fully generated and successfully saved. Once a module reaches this state it remains there for the rest of the run, giving you an at-a-glance record of everything that has finished.
  • Queued / Waiting: Modules that have been selected but have not yet started processing are shown as waiting. This distinguishes them clearly from modules that are actively running or have already finished.
  • Failed / Error: This indicator flags any module where generation did not complete successfully. It is visually distinct — typically a different color or icon — so it stands out immediately even in a long list of modules. It does not mean the batch has stopped; it simply marks that specific module as one requiring follow-up.

Consider a practical example. Suppose you launch a batch containing eight modules. After a few minutes the panel might look like this in terms of status:

Module Status Detail
Introduction to Data Types Completed All 5 topics generated and saved
Variables and Scope Completed All 6 topics generated and saved
Control Flow In Progress Topic 4 of 7
Functions and Closures Queued Waiting
Error Handling Queued Waiting
Working with APIs Queued Waiting
Data Structures Queued Waiting
Testing Fundamentals Queued Waiting

This kind of view makes the state of the entire batch immediately legible without needing to interpret logs or navigate away from the panel.

Overall Batch Completion Counter

Alongside the per-module status lines, the panel displays a summary-level completion counter. This counter shows the number of modules that have reached a completed state alongside the total number of modules included in the batch — for example, 3 of 8 modules completed. The counter increments each time an individual module transitions to the completed state, so it moves forward in discrete, observable steps throughout the run.

The practical value of the counter is in time estimation. If you know from experience that each module in your course takes roughly two to three minutes to generate, and the counter shows 4 of 10 modules completed after approximately ten minutes, you can reasonably estimate that the remaining six modules will take another fifteen to eighteen minutes. This helps you decide whether to stay at your desk and watch the panel through to completion or whether you have time to step away and return later.

It is worth noting that the counter reflects completed modules specifically — modules that end in an error state are counted separately and do not increment the completion counter. This keeps the counter an honest measure of successfully generated content rather than simply a measure of modules that are no longer actively processing.

Reading Generation Order and Queue Position

Modules are not processed in a random or unpredictable order. The batch processes modules in the order they were selected before the run was launched. This predictability is important: it means you can look at the panel and know not just what is happening now, but what will happen next.

The panel visually distinguishes between the currently active module, the completed modules above it, and the queued modules below it. The currently active module — the one carrying the In Progress indicator — is your anchor point. Everything above it is done; everything below it is still waiting its turn.

This queue visibility is particularly useful when you have a module you are especially eager to review. If you can see that the module you care about most is third in the queue and the current module is already at Topic 5 of 6, you know the module you are waiting for will begin very soon. Conversely, if your most important module is seventh of ten, you have time to do other work and return later without missing its generation window.

Interpreting Error or Warning Signals

One of the most important things to understand about error signals in the live progress panel is their scope. An error on one module does not automatically halt the entire batch. The failed module is marked with an error indicator, and the batch continues processing the remaining queued modules without interruption. This behavior is intentional and beneficial: a single problematic module should not block content generation for the other seven or seventeen modules in your batch.

When a module fails, the status line may display a brief warning message describing why generation did not complete successfully. Common reasons include connectivity interruptions, content policy flags on specific topic material, or timeouts during generation of a particularly complex topic. These brief messages give you enough information to understand the likely cause and plan a fix.

The recommended approach when you see error indicators appear during a run is straightforward: note which modules are flagged but do not interrupt the batch. Let the run complete in full. Once the batch is finished, you will address the failed modules individually — either by re-running generation for just those modules, adjusting their topic definitions, or investigating the specific warning messages more carefully. Attempting to intervene during the run itself is rarely necessary and can complicate the process.

Tracking Completion to Know When the Batch Has Finished

The batch run reaches its conclusion when every module has transitioned out of the In Progress or Queued state — that is, when every module has reached either a Completed or Failed/Error state. At this point, no further generation is occurring anywhere in the batch.

The panel signals this final state clearly. A concluding status message appears — something along the lines of Batch complete: 7 of 8 modules generated successfully, 1 module encountered an error — and the visual state of the panel changes to indicate that the run is fully done. The in-progress animation or activity indicator associated with the active module disappears, and the panel becomes static.

This final signal is your cue that it is safe to navigate away from the panel. You can now move into Course Manager's normal module view and begin reviewing the generated content in each completed module, checking topic bodies, making edits, or publishing material as appropriate. Any modules that ended in an error state are your priority follow-up items — they will contain no generated content and will need to be addressed before their material is available to learners.

Building the habit of reading the live progress panel fluently — understanding what each indicator means, how the counter reflects true completion, and how error signals should inform (but not necessarily interrupt) your workflow — makes batch generation a smooth, low-anxiety process even when running large course builds with many modules at once.
