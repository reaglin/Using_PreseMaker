Using the Course Repository Service

▶

PreseMaker includes built-in integration with an external Course Repository Service — a dedicated platform designed so that educators can share finished or in-progress course materials with one another and reuse content that colleagues have already built. Rather than forcing you to visit a separate website, download files manually, and then re-upload them into your project, PreseMaker handles every part of the exchange — browsing, importing, and publishing — from inside the application itself. Understanding what the service is, how to connect to it, and how it compares to PreseMaker's other sharing and version-control features will help you take full advantage of this collaborative content ecosystem.

The Course Repository Service is, at its core, a content-sharing network for instructors. Think of it as a library where educators deposit course materials they are willing to share and withdraw materials that other educators have deposited. An example of such a service is floridacourserepo.com, which aggregates course content from participating institutions and individual instructors. Any instructor whose PreseMaker installation is pointed at that service can browse its catalog, pull materials into their own project, adapt them, and — if they choose — contribute their own work back to the catalog so others can benefit in turn. The emphasis throughout is on reuse and collaboration around content, not on tracking a history of edits or producing a live website.

It is equally important to understand what the Course Repository Service is not. It is not a Git repository, and none of the concepts or mechanics associated with Git apply here. There are no commits, no branches, no merges, no pull requests, no personal access tokens, and no command-line interactions of any kind. The service exists purely to let instructors share course materials; PreseMaker abstracts away all of the underlying network communication so that the workflow stays visual and straightforward.

Connecting to the Repository Service from PreseMaker is the first practical step. Because the integration lives inside the application, you initiate and manage the connection entirely through PreseMaker's own interface — you never need to open a browser, navigate to the service's website directly, or configure anything outside the app. When you provide PreseMaker with the details it needs — typically the address of the repository service you want to use — the application stores those settings so that you do not have to re-enter them at the start of every working session. Once the connection is established, PreseMaker communicates with the external service in the background, presenting you with a familiar in-app experience rather than bouncing you between different tools.

The practical effect of this design is that switching between working on your own course content and interacting with the shared repository feels seamless. PreseMaker remembers where your repository service is located and handles authentication and communication on your behalf, keeping the focus on the course materials themselves rather than on the mechanics of connecting to an external system.

Importing course materials from the repository is one of the two primary actions the integration supports. Once your connection is active, PreseMaker gives you the ability to search or browse the catalog of materials that other educators have published. You might search by subject area, keyword, course level, or contributor, depending on what the service exposes. When you find something useful — a set of slides, a structured lesson, an assessment bank, or an entire course skeleton — you select it and PreseMaker imports it directly into your working project. The import process requires no manual downloading of files to your desktop and no separate re-uploading step; PreseMaker fetches the content and places it where you need it.

Once imported, the materials are fully yours to work with inside PreseMaker. You can use them exactly as they arrived — if a colleague has already built a well-structured module on a topic you also teach, you may find it needs little or no adjustment — or you can modify, extend, and reshape them to fit your own course design, terminology, and learning objectives. The repository model therefore saves time not just by providing ready-made content but by giving you a meaningful starting point that you can customize rather than building from a blank slate.

Publishing your own materials to the repository is the reciprocal action. When you have built course content that you believe would be valuable to other instructors — whether it is a polished, finished course or a strong working draft — PreseMaker provides a publish option that sends that content to the external repository service directly from within the application. Once published, your materials appear in the catalog and become importable by any other educator who uses the same repository service. You are contributing to the shared library in the same way you benefit from it when you import someone else's work.

Publishing in this context is focused entirely on content sharing and reuse. It is not about deploying a live website for students to visit, and it is not about creating a version snapshot for your own future reference. It is specifically the act of making your course materials available in a form that another instructor can import into their own PreseMaker project and build upon.

Because PreseMaker also includes other features that involve exporting or sharing your work, it is worth being precise about how the repository service differs from those other features. The table below summarizes the key distinctions:

Feature Primary Purpose Audience What It Produces
Course Repository Service Share and reuse course content with other instructors Other educators using the same repository service Importable course materials in the shared catalog
Git Version Control Track changes to your course over time; maintain a history of edits Yourself (and any collaborators on the same project) A versioned history of your project files
GitHub Pages Publishing Deploy your course as a live website with a public web address Students and anyone with the URL A publicly accessible website hosted on GitHub Pages

Git version control inside PreseMaker is concerned with your own course over time. Every time you commit a change, Git records a snapshot so that you can look back at earlier states of the course, understand what changed and when, and recover from mistakes. The repository service has nothing to do with this history-keeping function; it is not tracking the evolution of your work but rather making a version of that work available for others to take and use.

GitHub Pages publishing, meanwhile, is concerned with delivery to learners. When you publish to GitHub Pages, you are generating a live website — a public URL that students can open in a browser to view and interact with your course. This is a deployment action, not a sharing-with-colleagues action. A student visiting your GitHub Pages site cannot import your course into their own PreseMaker installation; they simply see the rendered output. The repository service, by contrast, makes the underlying course materials available in a form that another instructor can import and edit.

Keeping these distinctions clear helps you choose the right tool for each goal. If you want to save your progress and maintain a history, use Git. If you want to give students a website to visit, use GitHub Pages. If you want to share reusable course materials with fellow instructors or bring someone else's materials into your own project, use the Course Repository Service — all without leaving PreseMaker.
