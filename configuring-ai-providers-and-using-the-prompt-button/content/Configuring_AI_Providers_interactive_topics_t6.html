Interpreting and Responding to Generation Failures

▶

When you ask PreseMaker to generate content — whether that is a set of module topics, a quiz, a narration script, or a standards alignment — the application sends a request to an external AI provider on your behalf. A generation failure occurs when that request cannot be completed successfully. It is critically important to understand from the outset that a generation failure is not a sign that something is wrong with your course content, your writing, or the structure of your module. Instead, it signals a breakdown in the communication or configuration between PreseMaker and the AI provider it is trying to reach. Treating it as a configuration problem — rather than a content problem — immediately points you toward the right solutions.

Generation failures can surface during any AI-assisted task in PreseMaker. This includes generating module topics and subtopics, drafting learning outcomes, producing slide content, writing text lessons, creating quizzes, designing assignments, building interactive activities, composing narration scripts, and mapping content to standards. Because all of these tasks route through the same AI provider connection, a single misconfiguration will block every one of them simultaneously. Conversely, a single correct fix restores all of them at once.

The failure message that PreseMaker displays when generation does not succeed is your first and most valuable diagnostic clue. Before clicking retry or making any changes, read the message carefully. It will often indicate whether the problem is an authentication error (pointing to a missing or invalid API key), a quota or rate-limit error (pointing to provider-side usage restrictions), or a connectivity error (pointing to a possible service outage). Matching the language of the error message to the categories below will help you resolve the issue as efficiently as possible.

The three most common root causes of generation failures are a missing or invalid API key, no key on file for any provider at all, and provider-side issues such as outages or quota exhaustion. Each of these has a clear diagnosis path and a straightforward correction. Note that simply having the Active AI Provider dropdown set to a provider you have no key for is not one of these causes — PreseMaker handles that situation for you, as explained below.

A missing or invalid API key is the single most frequent cause of generation failures, especially for users who are setting up PreseMaker for the first time or who have recently changed their provider account. Every AI provider — OpenAI, Anthropic, Google, and others — requires that requests carry a valid credential in the form of an API key. If PreseMaker does not have a key on file, or if the key it has on file has been revoked, expired, or was entered incorrectly, every generation request will be rejected before any content is even processed.

To investigate this cause, open Settings and look at the API key fields. Confirm that at least one key is actually present, and that each key was entered in the field belonging to the provider that issued it. Each provider issues its own keys in its own format, and they are not interchangeable — an Anthropic key pasted into the OpenAI field will never authenticate. What matters is that a key sits in the right field; you do not have to worry about whether the Active AI Provider dropdown happens to point at that same provider, because PreseMaker resolves that for you.

Another key-related cause that is easy to overlook is key regeneration on the provider's side. Many developers periodically rotate their API keys for security reasons, and providers sometimes invalidate keys under certain account conditions. If you or your organization recently regenerated the key in the provider's developer portal, the old key stored in PreseMaker Settings is no longer valid even though it appears to be present. You must retrieve the new key from the provider's portal and update it in PreseMaker Settings to restore connectivity.

The second major cause is having no API key on file for any provider. This is worth stating carefully, because it is easy to assume a related problem exists when it does not. Suppose you enter an OpenAI key but leave the Active AI Provider dropdown set to Claude (Anthropic). PreseMaker does not try to authenticate your OpenAI key against Anthropic's servers, and it does not fail. When the selected provider has no key, PreseMaker automatically uses whichever provider does have one — in this example, OpenAI. Entering a single key is all the configuration PreseMaker needs, and if that is the only key you have entered, PreseMaker selects that provider for you.

Understand precisely what this automatic behavior is and is not. It happens when PreseMaker is choosing a provider, and it is based purely on which keys exist. It is not an error-recovery retry: once a provider has been chosen and its request fails — a rejected key, a rate limit, a network problem, a model error — PreseMaker does not quietly try a different provider. It stops and shows you the failure dialog. So a generation failure never means "PreseMaker picked a provider I had no key for." It means the provider it did pick returned an error, or you have no key anywhere.

To diagnose this, navigate to Settings and confirm that at least one API key field is populated. You only need one valid API key to use PreseMaker's AI features. If every field is empty, obtain a key from any one provider's developer portal and enter it in that provider's field. If a key is present and generation still fails, the key itself is the suspect — it may be invalid, expired, or revoked — and the fix is to replace it, not to change the dropdown.

The third category of causes involves provider-side issues — problems that originate with the AI service itself rather than with your PreseMaker configuration. These require a different approach because no amount of changes to your Settings will resolve them; the issue must clear on the provider's side first.

The two most common provider-side issues are service outages and quota or rate-limit exhaustion. Major AI providers publish real-time service status pages where you can confirm whether their APIs are experiencing disruptions. If a widespread outage is listed, the appropriate response is to wait until service is restored and then retry your generation task. There is nothing to fix in PreseMaker itself.

Quota and rate-limit issues are more nuanced. Every API plan comes with usage limits, which may be expressed as a maximum number of tokens per minute, requests per day, or a monthly spending cap. When you exceed these limits, the provider's servers will reject further requests until the limit resets — typically at the top of the next minute, the next day, or the next billing cycle, depending on the type of limit. Attempting to generate content repeatedly in a short period (for example, regenerating multiple modules in rapid succession) is a common trigger for rate limiting. The failure message will often include wording such as "rate limit exceeded" or "quota exhausted," which makes this cause identifiable. The appropriate responses are to wait a short time and retry, to upgrade your provider plan to a higher usage tier, or to temporarily switch the active provider to a different one for which you have a valid key with available quota.

With those causes established, a disciplined step-by-step diagnostic approach ensures you address the right problem efficiently without making unnecessary changes.

  • Step 1 — Identify the active provider. Open Settings and note which provider is currently selected in the Active AI Provider dropdown. This tells you which service PreseMaker is attempting to contact.
  • Step 2 — Verify the API key. Confirm that a valid, current API key for that exact provider is entered in the corresponding field and has been saved. Check both that it is present and that it belongs to the correct provider.
  • Step 3 — Check provider status and quota. If both the active provider and the key appear correct, visit the provider's public status page or log in to your account dashboard to look for reported outages, quota warnings, or rate-limit notifications.
  • Step 4 — Apply the correction and retry. After making any necessary change — updating a key, switching the active provider, or simply waiting for a rate limit to reset — retry the failed task. Because all AI tasks share the same provider connection, a successful fix will restore generation capability across every task type at once.

Taking corrective action follows directly from the diagnosis. The table below summarizes each cause, how to identify it, and the appropriate fix:

Cause How to Identify It Corrective Action
Missing API key Key field in Settings is empty for the active provider Obtain the API key from the provider's developer portal and enter it in PreseMaker Settings
Invalid or expired API key Key is present but generation returns an authentication error; key may have been regenerated Retrieve the current key from the provider's portal and replace the stored key in Settings
Mismatched active provider Key belongs to Provider A but Active AI Provider dropdown is set to Provider B Change the dropdown to match the key you have, or enter the correct key for the selected provider
Provider service outage Status page shows an incident; error message references a server or connectivity issue Wait for the outage to resolve, then retry; no Settings changes needed
Quota exhausted or rate limited Error message references rate limits or quota; failures occur after heavy use Wait for limit to reset, upgrade the provider plan, or switch active provider to one with available quota

To fix a missing key, log in to the developer or API portal of your chosen provider (for example, platform.openai.com for OpenAI or console.anthropic.com for Anthropic), locate the API keys section, copy your key, and paste it into the appropriate field in PreseMaker Settings. Save the settings before retrying generation.

To fix a mismatched active provider, the simplest approach is usually to open the Active AI Provider dropdown and select the provider that matches the key you already have saved. For instance, if you have an Anthropic key entered and the dropdown currently reads "GPT-4o," switching it to "Claude" will immediately align the configuration. Alternatively, if you prefer a specific provider, obtain a key from that provider's portal and enter it, leaving the dropdown as-is.

To address a quota or rate-limit issue, consider the urgency of your work. If the limit will reset shortly (common for per-minute rate limits), simply waiting a few minutes before retrying is the most practical solution. If you are on a free or low-tier plan and regularly hitting limits, upgrading to a paid or higher-tier plan with your current provider will expand your capacity. A third option — particularly useful when you need to continue working immediately — is to enter a valid key for a different provider and switch the Active AI Provider dropdown to that provider, effectively bypassing the exhausted quota on your primary account.

Understanding generation failures as configuration and communication problems rather than content problems transforms what can feel like a frustrating obstacle into a solvable technical checklist. By reading the failure message carefully, matching it to the known causes, and working through the diagnostic steps in order, you can restore full AI generation capability in PreseMaker quickly and with confidence.
