Using the Prompt Button to Inspect AI Requests

▶

Every time PreseMaker generates content — whether that is a set of learning outcomes, a quiz, a narration script, or a full slide — it constructs a text-based request and sends that request to whichever AI provider you have selected. The Prompt button gives you a direct window into that process. Clicking it reveals the exact text PreseMaker has assembled for the current task, so you can see precisely what the AI provider will receive before or after generation takes place. This transparency is valuable both for routine verification and for systematic troubleshooting, and understanding how to use it effectively will make your workflow more predictable and easier to manage.

The Prompt button is available across all text-based generation tasks in PreseMaker. This includes, but is not limited to, generating module topics, learning outcomes, slide content, quizzes, assignments, narration scripts, and standards alignment. In every one of these cases, the text displayed is the complete, unmodified request — PreseMaker does not append hidden instructions, silent system messages that alter meaning, or any other undisclosed additions after the prompt is shown. What you see is exactly what the provider receives.

It is also worth noting what the prompt will never contain: because PreseMaker performs exclusively text-based AI tasks, you will not encounter image generation instructions, vision-model directives, or any multimedia processing commands in any prompt. The scope is intentionally and entirely textual.

Knowing when to click the Prompt button is just as important as knowing what it does. There are two primary moments when reviewing the prompt adds the most value:

  • Before generation: Clicking the Prompt button before you trigger generation lets you confirm that the request has been constructed correctly for the task at hand. For example, if you are generating quiz questions for a specific module topic, you can verify that the correct topic title, context, and any relevant content settings are reflected in the prompt text before the AI provider ever processes it. This is especially useful when you have recently made changes to your course structure or settings.
  • During troubleshooting: If the AI returns output that seems off — questions that do not match the topic, narration that ignores your course tone, or outcomes that feel too generic — the Prompt button helps you isolate the cause. If the prompt text looks correct and complete, the issue likely lies with the provider's response, your API key configuration, or provider availability. If the prompt text itself is missing context or contains incorrect details, that is where you should focus your corrections before regenerating.

To use the Prompt button effectively, you need to understand what shapes the text it displays. The prompt is constructed automatically by PreseMaker based on the specific generation step you are performing and the context associated with that step. This context includes elements such as your course structure, the topic or subtopic details you have entered, any content or tone settings you have configured, and the nature of the task itself (for instance, whether you are generating a formative quiz or a summative assignment). You do not have to write the prompt yourself — PreseMaker builds it for you, and the Prompt button makes that constructed text visible. When the prompt preview opens for a single generation call, you may also adjust the text before sending it, and PreseMaker will send exactly what the preview shows. When a single action drives several AI calls at once (for example, generating a document per topic), the preview is read-only: it shows the shared system prompt plus each call's user prompt so you can inspect them, but edits there are not sent.

Because the prompt is derived from your course content and settings, the quality and completeness of what you see in the prompt is directly tied to the quality and completeness of what you have entered into PreseMaker. A topic description that is vague or sparse will produce a prompt that reflects that sparseness, and a more detailed, well-structured topic entry will produce a richer, more specific prompt. Reviewing the prompt text therefore also serves as an indirect audit of your course content.

The Active AI Provider setting has a direct relationship with the Prompt button. In PreseMaker's Settings, the Active AI Provider dropdown determines which provider handles every generation request — and this applies universally, meaning the same provider that will process the prompt you are viewing is the one currently selected in that dropdown. If you switch providers in Settings, all subsequent prompts will be routed to the newly selected provider. The prompt text itself does not change based on which provider is active, but the provider that receives it does. This distinction matters when you are evaluating whether a particular provider is interpreting your prompt as expected.

Switching providers is a common reason to use the Prompt button as a verification step. After changing your active provider, reviewing the prompt for your next generation task confirms that the request content and structure are still producing the results you want from the new provider. Different providers can respond differently to the same prompt text, and catching a mismatch early — before running multiple generations — saves both time and API usage.

When you are diagnosing a generation problem, a structured approach using the Prompt button leads to faster resolution. The table below outlines the most common scenarios and the recommended action based on what you observe:

What You Observe Prompt Looks Correct? Recommended Next Step
AI output does not match the topic or task No — context is missing or wrong Update your course content or settings, then review the prompt again before regenerating
AI output does not match the topic or task Yes — prompt looks accurate and complete Investigate the provider's response behavior; consider testing with a different provider
Generation fails entirely or returns an error Yes — prompt looks accurate and complete Check your API key configuration and verify that your selected provider is currently available
Output quality dropped after switching providers Yes — prompt is unchanged Compare how the new provider interprets the same prompt; adjust provider selection or settings as needed
Output is unexpectedly generic or shallow No — topic details are sparse in the prompt Enrich your topic descriptions and content settings, then regenerate

In practice, developing the habit of checking the Prompt button before high-stakes generation tasks — such as producing a full module's worth of slides or a comprehensive assessment — can prevent the frustration of discovering a structural problem only after consuming API resources and time. Think of it as a pre-flight check: a brief review of the prompt text costs very little effort and provides meaningful assurance that the request going to your AI provider is the request you actually intend to send.

To summarize the key behaviors of the Prompt button: it displays the complete and unmodified text that PreseMaker constructs for the current task; it works across all text-based generation tasks; the text reflects your current course context and settings; it is tied to your active provider selection without altering the prompt text itself; and it serves as your primary diagnostic tool for distinguishing between prompt-level issues and provider-level issues. Used consistently, it gives you meaningful visibility into the AI generation process without requiring any technical knowledge of how prompts are structured internally.
