The Active AI Provider Setting

▶

Every AI-powered action in PreseMaker — whether it is generating module topics, building quiz questions, drafting speaker narration, or producing any other content — is processed by a single, centrally configured provider. That provider is determined entirely by one control: the Active AI Provider dropdown located in the application's Settings area. Understanding how this setting works, what it governs, and why it is designed this way is essential before you begin any AI-assisted content creation in PreseMaker.

The Active AI Provider dropdown is the singular point of control for all AI functionality in PreseMaker. You will find it inside the Settings area of the application. When you open that dropdown and select a provider — for example, OpenAI, Anthropic, Google Gemini, or whichever options the current version surfaces — that selection immediately becomes the governing choice for every AI operation the application will perform from that moment forward. There is no secondary control, no per-feature override, and no hidden default that operates in the background independently of this dropdown. Whatever appears selected in that dropdown is the active provider, full stop.

It is worth being precise about the scope of the phrase every AI task. PreseMaker performs AI generation across a range of content types during a typical authoring session. Consider the variety of work the application can hand off to an AI provider:

  • Generating module topics and subtopic outlines from a subject description
  • Writing detailed body content for each topic
  • Producing quiz questions, answer choices, and feedback text
  • Drafting speaker narration scripts tied to slide content
  • Suggesting titles, summaries, or other supplementary text

Every item on that list — and any other AI-driven generation the application performs — is routed to the one provider currently selected in the Active AI Provider dropdown. There is no scenario in which module topic generation travels to one provider while quiz generation travels to another. The architecture does not allow it. A single selection governs all of it simultaneously.

This point deserves its own emphasis because it is a common source of confusion for users who have experience with other platforms that allow granular, per-task AI routing. No per-task provider assignment exists in PreseMaker. There is no interface panel where you can specify "use Provider A for slide content and Provider B for assessments." There is no concept of a default provider for unassigned tasks that sits quietly in the background handling overflow work. The dropdown in Settings is the only configuration that matters, and it applies universally. Attempting to look for task-level routing options will not be productive — no such options are present in the current version of the application.

The unified design of this setting carries meaningful practical benefits. Because every AI task flows through the same provider and the same API key, configuration is dramatically simplified. If generation succeeds for one task — say, a module outline is produced without error — you can be confident that the same provider and key will work for every other task you ask PreseMaker to perform. You never need to audit multiple providers to confirm they are all correctly set up. There are no gaps where some tasks might have no assigned provider and silently fail for a configuration reason rather than a content reason.

Troubleshooting errors also becomes more straightforward under this model. If something goes wrong during AI generation, there is only one provider's status and one API key to inspect. You do not need to trace which task was being performed at the time of failure and then determine which of several providers that task was assigned to. The answer is always the same: check the provider currently selected in the Active AI Provider dropdown and verify that its key is valid, active, and has sufficient quota.

When it comes to choosing which provider to make active, there are a few practical steps to follow. You must first obtain an API key from the provider you intend to use. Each of the major AI providers — OpenAI, Anthropic, Google, and others — issues API keys through their respective developer portals, typically after you create an account and, in most cases, set up a billing method. Once you have that key, you enter it into the appropriate field in PreseMaker's Settings area. Only after a valid key has been entered for a provider can that provider be meaningfully selected in the Active AI Provider dropdown.

Importantly, you do not need accounts with all available providers. PreseMaker only requires a key for the provider you plan to use. If you have an OpenAI key and you select OpenAI as your active provider, that is a complete and fully functional configuration. You are not expected to populate keys for every provider listed — only the one you intend to activate.

Switching the active provider at any point is simple: open the dropdown in Settings, select a different provider, and save. From that moment forward, all AI generation will use the newly selected provider — provided, again, that a valid API key for that provider has been entered. The switch is immediate; there is no restart or cache-clearing required. If you find that a particular provider produces output that better suits your content style, or if you are managing costs across different provider pricing tiers, you can change the active selection freely. Just be aware that the moment you switch, all subsequent generation goes to the new provider, not just certain task types.
