Assigning AI Providers to Task Types

▶

PreseMaker allows you to take precise control over which AI provider handles each specific kind of generation task it performs. Rather than routing all AI work through a single provider, the platform lets you map individual task types to whichever provider best fits your goals — whether that means minimizing cost, maximizing speed, or ensuring the highest-quality output. This configuration lives in Settings and takes effect immediately the next time PreseMaker executes a task of the relevant type. Understanding how this system works, what task types are available, and how the default provider fits into the picture gives you the foundation to build a well-optimized authoring workflow.

Accessing Provider Assignment in Settings

All provider assignment configuration is managed from within PreseMaker's Settings area. When you navigate to Settings, you will find each available task type listed, and alongside each one you can view and edit which provider is currently mapped to it. The providers available for assignment are those you have already configured in PreseMaker — you must first add and authenticate a provider before it can be selected for any task type.

The mapping interface is intentionally straightforward: each task type has exactly one assigned provider at any given time, and you simply select from your available providers to change it. Once you save your changes, PreseMaker begins using the newly assigned provider the very next time it runs a task of that type. There is no restart required and no caching of old assignments — the routing logic reads the current configuration at the moment each task is triggered.

Understanding Task Types

PreseMaker supports a defined set of task types, each representing a distinct kind of content generation the platform performs during course authoring. Every one of these task types is text-based — PreseMaker does not include image generation or vision (image-reading) capabilities, so every assignable task works purely with text input and output. The full set of task types you can independently assign includes:

  • Module topics — generating the topic structure and subtopic breakdown for a module
  • Learning outcomes — producing measurable objectives that describe what learners will be able to do
  • Presentation slide content — drafting the text that appears on individual slides within a presentation
  • Text lessons — writing longer-form instructional body text for lesson pages
  • Quiz questions — creating assessment questions, including stems, correct answers, and distractors
  • Assignments — generating assignment prompts and descriptions
  • Interactive-activity content — producing content for interactive learning activities
  • Speaker narration — writing the spoken-word script that accompanies slides or lessons
  • Standards — generating or aligning content to educational or industry standards

Because each of these task types serves a different authoring purpose and has different characteristics — some are high-volume, some are high-visibility, some demand stylistic precision — the ability to assign them to different providers is directly useful in practice.

The Default Provider for Unassigned Tasks

Not every task type needs to have a specific provider explicitly assigned to it. If a task type has no provider selected, PreseMaker automatically routes it to a designated default provider, which you also configure in Settings alongside your task-specific assignments. The default provider is a safety net for configuration gaps — it ensures that PreseMaker can always attempt to execute any task type even if you have not made a deliberate choice for it.

It is important to understand what the default provider is not: it is not an automatic retry mechanism. If a task type has a specific provider assigned and that provider is unavailable or returns an error, PreseMaker does not silently fall back to the default. The default provider only comes into play when no specific provider has been assigned to a task type, not as a secondary option when the primary assignment fails. This distinction keeps routing behavior transparent and predictable — you always know which provider was attempted for any given task.

Assigning Different Providers to Different Tasks

The practical power of the assignment system is the freedom to mix providers across task types according to your own priorities. Consider a straightforward example: you might assign a capable, cost-effective provider to quiz question generation because you produce a large number of questions across many modules, and the cost of a premium provider at that volume would be significant. At the same time, you might assign a higher-capability premium provider to slide content generation because those slides are highly visible to learners and the quality of language directly affects the learner experience.

There are no artificial constraints on how you configure the mapping. Multiple task types can share the same provider — for instance, you might use the same provider for both learning outcomes and standards because they are closely related and you want stylistic consistency between them. Alternatively, every task type could be assigned to a different provider if your evaluation of each one led to that conclusion. The system imposes no minimum or maximum on provider diversity across the task map.

How PreseMaker Routes a Task to a Provider

The routing logic PreseMaker uses is a simple, direct lookup. When a generation request is triggered — for example, when an author asks PreseMaker to generate quiz questions — the platform checks the task-type-to-provider mapping for that task type. If a provider is specifically assigned, that provider receives the request. If no specific assignment exists, the default provider receives the request. There is no ranked list, no priority queue, and no secondary fallback provider.

This design means routing is consistent and predictable. Every generation request for a given task type goes to the same provider every time, as long as the Settings configuration has not changed. Authors do not need to wonder which provider handled a particular output or whether a fallback silently changed the source of a generation. The one-to-one mapping at any given moment makes the system easy to reason about and easy to troubleshoot if output quality or cost patterns are not meeting expectations.

Choosing a Provider Based on Cost, Speed, or Quality

The decision of which provider to assign to each task type naturally involves weighing three practical dimensions: cost, speed, and output quality. These considerations often pull in different directions, and the assignment system gives you the flexibility to make different trade-offs for different tasks rather than accepting a single compromise across the board.

Cost becomes a significant factor for high-volume tasks. Quiz distractor generation, for example, might be executed dozens or hundreds of times across a course build. Assigning a less expensive provider to that task type — even if its output is slightly less polished — can produce meaningful savings without affecting the parts of the course that learners notice most. Lower-stakes background tasks, where the output feeds into a process rather than appearing directly in front of learners, are natural candidates for cost-optimized providers.

Speed matters most for tasks that are run frequently within a single authoring session, or for tasks where an author is actively waiting for output before proceeding. If a particular provider returns results significantly faster than others for a given task type, assigning that provider can meaningfully reduce idle time during content development. This is especially relevant for iterative tasks where an author might regenerate output multiple times to find a version they want to keep.

Quality justifies premium provider assignment for high-visibility or high-stakes outputs. Slide content, learning outcomes, and text lessons are seen directly by learners and reflect on the overall quality of the course. Speaker narration must read naturally when converted to audio. For these task types, the incremental cost of a more capable provider is often well justified by the improvement in output that reaches the learner. The following table summarizes how these three dimensions might guide typical assignment decisions:

Task Type Primary Consideration Rationale
Presentation slide content Quality Directly visible to learners; language quality has high impact on course perception
Learning outcomes Quality Sets expectations for the entire module; precision and alignment matter significantly
Speaker narration Quality / Speed Must read naturally; iterative regeneration during authoring makes speed valuable too
Text lessons Quality Extended instructional content where coherence and clarity directly affect learning
Quiz questions Quality / Cost Assessment integrity matters, but volume can be high across a full course build
Assignments Quality Prompts need to be clear and well-scoped; typically lower volume than quiz questions
Interactive-activity content Quality / Speed Learner-facing; iterative refinement during authoring is common
Module topics Speed / Cost Structural scaffolding task; often run early and quickly revised by the author
Standards Quality Alignment accuracy is important for compliance and credentialing contexts

These are guiding patterns rather than fixed rules. Your specific provider options, the volume of content you produce, and the standards your organization applies to learner-facing material will all influence where you land on each task type. The value of the assignment system is precisely that it lets you apply your own judgment task by task rather than accepting a uniform approach across all of PreseMaker's generation work.
