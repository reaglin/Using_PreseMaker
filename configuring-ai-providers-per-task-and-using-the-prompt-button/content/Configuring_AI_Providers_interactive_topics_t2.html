Obtaining and Entering API Keys

▶

To use any of PreseMaker's AI-powered features, you must supply at least one valid API key from a supported AI provider. An API key is a unique credential — essentially a long string of characters — that identifies your account to the AI provider's servers, authorizes your requests, and links any usage costs back to your account. Without a key, PreseMaker has no way to communicate with external AI models. This topic walks through every step of the process: understanding which providers are supported, navigating their developer portals to generate a key, entering that key inside PreseMaker, and understanding exactly how PreseMaker protects your credentials once they are stored.

The Four Supported AI Providers

PreseMaker integrates with four major AI providers, each of which is an independent company operating its own platform, pricing model, and developer infrastructure. The table below summarizes the four providers and the primary model or product family associated with each:

Provider Primary Model / Product Developer Portal URL
Anthropic Claude console.anthropic.com
OpenAI GPT-4o platform.openai.com
Google Gemini aistudio.google.com / console.cloud.google.com
xAI Grok console.x.ai

Because each provider is a separate company, the sign-up process, billing setup, free-tier availability, and key management interface differ from one portal to the next. However, the general workflow is the same across all four: create an account, add a payment method if required, navigate to the API keys section, and generate a new key. You do not need keys from all four providers. Obtaining a key from even one of them is sufficient to begin using PreseMaker's AI features immediately.

Acquiring an API Key from a Provider

The steps below describe the general process that applies to all four supported providers. Where the experience differs meaningfully, provider-specific notes are included.

  • Navigate to the official developer portal. Always start from the provider's official website to avoid phishing sites. Bookmark the correct URL from the table above. For example, to obtain a Claude key you would go to console.anthropic.com; for GPT-4o you would go to platform.openai.com.
  • Create or log in to your account. Most providers allow you to register with an email address or an existing Google or GitHub account. Some providers, including OpenAI and Anthropic, require you to verify a phone number during initial sign-up as an anti-abuse measure.
  • Set up billing if required. Free trial credits are available on some platforms for new accounts, but production API access generally requires a valid payment method on file. Add your billing information before attempting to generate a key, as some portals will not display the key-creation option until billing is configured.
  • Locate the API Keys section. Once logged in, look for a menu item labeled API Keys, Credentials, or similar — typically found in the left-hand navigation sidebar or under account/settings menus. In the Anthropic Console this is directly in the main navigation; on OpenAI's platform it is under your profile icon in the top-right corner.
  • Generate a new key. Click the button labeled Create new secret key, Generate key, or equivalent. Some portals allow you to assign a descriptive name to a key (for example, "PreseMaker - Work Laptop"), which makes it easier to identify and revoke specific keys later if needed.
  • Copy the key immediately. This is a critical step. Most providers display the full key only once — at the moment of creation. Once you navigate away from that screen, the key is no longer shown in full; only a masked or truncated version appears for reference. Copy the key to your clipboard right away, before closing or refreshing the page. If you forget to copy it, you will need to delete the old key and generate a new one.

A newly generated API key typically looks like a long, random string of letters, numbers, and sometimes hyphens. For example, an OpenAI key begins with the prefix sk- followed by a long alphanumeric sequence:

sk-proj-A1b2C3d4E5f6G7h8I9j0K1l2M3n4O5p6Q7r8S9t0...

Anthropic keys begin with sk-ant-, while other providers have their own formats. The exact format is not something you need to memorize — what matters is that you copy the entire string without adding any spaces or line breaks.

Entering Your API Key in PreseMaker Settings

Once you have copied your key, switch to PreseMaker and follow these steps:

  • Open the Settings panel. In PreseMaker, navigate to the Settings area. This is typically accessible from the main menu or a gear icon in the application toolbar. The Settings panel contains configuration options for the application, including all AI provider integrations.
  • Locate the API key entry fields. Within Settings, you will find clearly labeled text fields for each of the four supported providers — Anthropic, OpenAI, Google, and xAI. Each field is dedicated to one provider's key and will not accept a key intended for a different provider.
  • Paste your key into the correct field. Click into the field that corresponds to the provider whose key you just generated and paste your key. Ensure you are pasting into the matching provider's field. For example, an Anthropic Claude key must go into the Anthropic field — entering it in the OpenAI field will result in failed API requests because the key format and authentication endpoint will not match.
  • Save your settings. Click the Save or Apply button to confirm your entry. PreseMaker will process and store the key at this point. After saving, the field will typically display a masked representation (for example, sk-ant-••••••••••••••••••••••••WXYZ) to confirm the key is stored without exposing it visually.

Secure Storage with Windows DPAPI

A legitimate concern whenever software stores credentials is: how safe is that storage? PreseMaker addresses this by using the Windows Data Protection API (DPAPI), a built-in encryption facility provided by the Windows operating system itself.

Here is how the protection works in practice:

  • Immediate encryption on save. The moment you click Save in PreseMaker's Settings, your API key is encrypted using DPAPI before it is written to disk. The plaintext key never sits unprotected on your file system — even momentarily after saving.
  • Storage location. The encrypted key is written to a file called app_settings.json, located inside your Windows user profile directory. A typical path looks like this:
C:\Users\YourUsername\AppData\Roaming\PreseMaker\app_settings.json
  • User-account binding. DPAPI ties the encrypted data to the specific Windows user account that performed the encryption. This means that even if another user on the same computer were to copy app_settings.json to their own profile, they could not decrypt the keys — the decryption will fail because it is happening under a different user account. This is a strong, OS-enforced protection that does not rely on PreseMaker storing its own master password.
  • No master password to remember. Because DPAPI uses your Windows login session as the root of trust, you do not need to create or remember a separate encryption password for your API keys. The protection is seamless and automatic.

Keys Are Never Shared or Stored in Course Files

PreseMaker is designed so that your API credentials are entirely separate from your course content. This separation is intentional and important, especially for teams or anyone who publishes or distributes course projects.

  • Keys live only in your local settings file. Your API key data exists solely inside app_settings.json on your local machine. Course project files — the files that define your slides, questions, media, and structure — contain no API key data whatsoever.
  • Safe to share, export, and push. When you share a course file with a colleague, export it for delivery, or push it to a version control repository such as Git, you can do so with full confidence that no credentials are embedded in those files. A collaborator who opens your course project in their own copy of PreseMaker will see all your content but will be prompted to supply their own API key.
  • No risk of accidental credential leakage. Because the architecture enforces this separation at the file level rather than relying on the user to remember to remove sensitive data before sharing, there is no scenario in which an API key could accidentally travel with a course file.

Minimum Key Requirements

Before PreseMaker's AI features become functional, a small but firm set of conditions must be met:

  • At least one valid key must be present. PreseMaker requires a minimum of one active, valid API key stored in Settings. If no key has been entered at all, every AI-powered feature — content generation, question creation, feedback drafting, and so on — will be unavailable or will display an error prompting you to configure a key.
  • The active provider and the stored key must match. PreseMaker's Settings include an Active AI Provider dropdown that determines which provider's model PreseMaker will use for AI requests at any given time. If you select Anthropic (Claude) as your active provider but have only entered an OpenAI key — or have entered the Anthropic key in the wrong field — AI requests will fail. The key stored must correspond to the currently selected active provider.
  • Multiple keys for flexibility. You may optionally enter keys for more than one provider simultaneously. Doing so gives you the flexibility to switch the Active AI Provider dropdown between, for example, Claude and GPT-4o without needing to re-enter credentials each time. This is useful for comparing outputs between models or for switching to a different provider if one is temporarily unavailable.
  • Validate your key before heavy use. An easy way to confirm a key is working is to attempt a small AI action in PreseMaker immediately after saving the key. If the action completes successfully, the key is valid and correctly matched to the active provider. If you receive an authentication error, double-check that you copied the full key without truncation, that it is in the correct provider field, and that the active provider dropdown matches.
