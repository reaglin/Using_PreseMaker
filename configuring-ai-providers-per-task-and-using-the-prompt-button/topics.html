Configuring AI Providers per Task and Using the Prompt Button — Module Topics

Introduction to AI Providers in PreseMaker

An overview of the four AI providers supported by PreseMaker and how they are used to handle text-based generation tasks. This topic establishes the foundational context for configuring and working with AI providers.
  • What PreseMaker Uses AI Providers For — PreseMaker relies on AI providers exclusively for text-based generation tasks across the course-building workflow.
  • The Four Supported AI Providers — PreseMaker supports exactly four AI providers: Claude (Anthropic), Gemini (Google), GPT-4o (OpenAI), and Mistral AI.
  • How API Keys Are Stored and Secured — When you enter an API key into PreseMaker's Settings, the application encrypts and stores it securely on your local machine.
  • The Active AI Provider Setting — PreseMaker uses a single Active AI Provider setting in Settings to determine which provider handles all AI requests.
  • One Provider Handles Every Task — No Per-Task Routing — There is no mechanism in PreseMaker to assign different AI providers to different types of tasks — one active provider serves all tasks universally.

Obtaining and Entering API Keys

How to acquire an API key from a supported AI provider and enter it in PreseMaker's Settings. This topic also covers how keys are securely stored using Windows DPAPI and what minimum key requirements exist.
  • The Four Supported AI Providers — PreseMaker is compatible with four AI providers, each requiring its own API key obtained directly from the provider's platform.
  • Acquiring an API Key from a Provider — To obtain an API key, you must create a developer or API account with your chosen AI provider and generate a key through their platform.
  • Entering Your API Key in PreseMaker Settings — Once you have your API key, you enter it in PreseMaker's Settings panel, where it is associated with the corresponding provider.
  • Secure Storage with Windows DPAPI — PreseMaker encrypts every API key using Windows Data Protection API (DPAPI) before storing it, ensuring keys are protected at rest on your machine.
  • Keys Are Never Shared or Stored in Course Files — API keys remain entirely local to your machine and are never embedded in course content or transmitted to a repository.
  • Minimum Key Requirements — You do not need to configure API keys for all four providers — a single valid key for one provider is the minimum requirement to enable AI features in PreseMaker.

The Active AI Provider Setting

An explanation of the single Active AI Provider dropdown in Settings and how the selected provider handles every AI task in PreseMaker. This topic clarifies that one provider is responsible for all generation work simultaneously.
  • What the Active AI Provider Setting Is — In PreseMaker's Settings, there is a single dropdown called the Active AI Provider, which determines which AI service handles all generation work in the application.
  • One Provider Covers Every AI Task — The selected Active AI Provider handles all text-based generation tasks in PreseMaker simultaneously — there is no division of responsibility between providers.
  • No Per-Task Provider Assignment Exists — PreseMaker does not allow you to assign different AI providers to different types of tasks; the application has no routing table or per-task dropdown of any kind.
  • Why a Single Active Provider Simplifies Configuration — The single Active AI Provider model was designed to eliminate the confusion that arose when different tasks were silently routed to different providers, which could cause unexpected failures.
  • Choosing Which Provider to Make Active — PreseMaker supports four AI providers — Claude (Anthropic), Gemini (Google), GPT-4o (OpenAI), and Mistral AI — and you select the one you want to use from the Active AI Provider dropdown after entering its API key.

Understanding That There Is No Per-Task Provider Assignment

A focused clarification that PreseMaker does not support routing different task types to different providers, and why that feature was removed. This topic corrects common misconceptions and explains the simplified single-provider model.
  • The Single-Provider Rule — PreseMaker uses exactly one active AI provider for every task it performs, with no exceptions.
  • What Per-Task Assignment Means — and Why It Does Not Exist — Per-task provider assignment would mean routing specific task types — such as quizzes or narration — to different AI providers, but PreseMaker does not support this.
  • Why the Feature Was Removed — An earlier version of PreseMaker did include per-task provider assignment, but it was deliberately removed because it caused significant user confusion.
  • Correcting Common Misconceptions — Because per-task routing existed in an older version, some users arrive with the expectation that different tasks can still be sent to different providers.
  • Practical Implication: One Key Is All You Need — Because every task uses the same provider, you only need to obtain and configure a single API key to use all of PreseMaker's AI features.

Using the Prompt Button to Inspect AI Requests

How to use the Prompt button to view the exact text sent to the active AI provider before or during generation. This topic helps learners understand and verify the input their chosen provider receives.
  • What the Prompt Button Does — The Prompt button allows you to inspect the exact text that PreseMaker will send to your active AI provider before or during generation.
  • When to Use the Prompt Button — The Prompt button is most useful when you want to verify, troubleshoot, or simply understand the input being sent before committing to a full generation.
  • Understanding the Text Shown in the Prompt — All AI tasks in PreseMaker are text-based, so every prompt you inspect will be a text request — there are no image or vision requests.
  • The Prompt Reflects Your Active Provider Selection — Because PreseMaker uses a single active AI provider for all tasks, the prompt you inspect is always destined for that one selected provider.
  • Verifying Input to Diagnose Generation Issues — The Prompt button is a practical diagnostic tool when AI output does not match your expectations, letting you rule out input-side problems.

Interpreting and Responding to Generation Failures

What generation failure messages mean and how to respond to them effectively. This topic guides learners through diagnosing common causes of failed AI requests and taking corrective action.
  • What a Generation Failure Means — A generation failure occurs when PreseMaker sends a request to the active AI provider and does not receive a successful response.
  • Common Cause: Missing or Invalid API Key — The most frequent cause of a generation failure is that the API key for the active provider is absent, incorrectly entered, or has been revoked by the provider.
  • Common Cause: Wrong Active Provider Selected — PreseMaker uses a single Active AI Provider for every task, so selecting a provider whose key has not been entered will cause all AI requests to fail.
  • Common Cause: Provider-Side Issues — Even with a correct key and active provider, failures can occur due to outages, rate limits, or quota exhaustion on the provider's platform.
  • Diagnosing the Failure: A Step-by-Step Approach — Effective diagnosis follows a consistent order: verify the active provider, verify the key, then look outward to the provider's platform.
  • Taking Corrective Action — Once the cause is identified, corrective actions are straightforward and typically require only a Settings update or a provider account action.
